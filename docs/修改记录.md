# 修改记录

## 2026-07-08：角色池、敌方卡组模板与难度曲线底座

- `EnemyDatabase.gd` 从旧的单一敌人轮换改为三段结构：通用角色池、敌方卡组模板池和难度曲线。
- 角色池开始同时收纳玩家可选角色基础模板、普通敌人、精英 / 首领候选和未来召唤物可引用单位；玩家局外成长仍由 `JobDatabase` / `MetaProgression` 包装，不直接写进角色池。
- 敌方生成顺序固定为：主线层数 + 节点位置 + 战斗类型 + 世界难度先选择敌方卡组模板；卡组模板再声明可引用的角色、站位、敌方阵营卡组、抽牌数、出牌上限和主题标签。角色模板只作为被引用的单位数据，不反向决定卡组。
- 难度曲线按层数、地图节点位置、遭遇类型和 `world_difficulty` 输出生命 / 攻击 / 防御修正；当前世界难度默认 0，只作为后续劫数入口预留。
- `BattleManager` 改为先读取敌方卡组模板生成的完整遭遇，再实例化主敌人和额外敌方单位；外部 `start_run_with_deck(...)` 参数保持兼容。
- `PrototypeSmokeTest.gd` 增加角色池、每层首领卡组模板数量、世界难度加成和遭遇单位装配检查。
- 架构迁移后回调默认世界难度 0 的模板强度：当前标准模板主要保持单敌方单位，多单位留给后续内容或更高世界难度，避免底层迁移直接抬高主线难度。
- 最新 `SwordProgressionProbe.gd` 固定种子结果：0 成长三层连续约 60.0%，两级生命约 66.3%，两级生命 +1 攻击约 83.8%，开放第二批且总分 +2 约 92.5%，三批成熟档约 88.8%，基础抽牌 +1 档为 100%。

## 2026-07-07：角色成长页分组展示

- `MetaProgression` 的成长项增加轻量 `category` 元数据，用于 UI 分组，不改变存档结构、成长数值或购买逻辑。
- 角色准备页的“角色成长”现在显示称号、可用 / 累计修为点、当前生命、攻防、基础抽牌和卡组总分上限。
- 成长项按“基础属性 / 卡组与卡包 / 角色特性 / 强力规则”分组展示，并在说明中直接显示下级消耗和修为点是否足够。
- `RunFlowSmokeTest.gd` 增加成长页标题、资源摘要和基础属性分组检查。

## 2026-07-07：角色准备页开局构筑

- 角色准备页按钮从“初始牌组”调整为“开局构筑”，进入后可在当前卡组和备选池之间移动卡牌。
- 开局构筑使用“职业默认开局牌 + 当前已开放编号卡包每卡 1 张”的临时备选池；默认开局牌中未开放卡包的特例牌仍作为开局牌保留，但不会额外进入奖励池。
- 开始挑战会把准备页当前卡组传入 `RunState`；准备页备选池不作为探索备牌带入，避免未选卡开局即可在坊市出售。
- 如果构筑不满足 10-20 张或卡组总分上限，会阻止开始挑战。
- 当前不做永久收藏、卡牌库存和同名上限；这一步只用于让玩家在正式进入探索前调整本轮开局卡组。
- `RunFlowSmokeTest.gd` 增加开局构筑页容器和开始挑战信号中的卡组 / 备选池检查。

## 2026-07-07：卡包解锁入口强化

- 修正低卡包阶段 Boss 奖励候选过窄的问题：按遭遇类型和分数过滤后如果候选少于 3 张，会在同一已解锁卡包范围内放宽分数下限，不会放开未解锁卡包。

## 2026-07-07：三层主线骨架第一阶段

- 层间推进只刷新地图、提升敌方层级参数并回复生命，不提供局内境界属性成长，避免旧的 Boss 后突破系统回流。

- 隐藏 Boss、完整牌手对手、Boss 连战和劫数明确为通关后系统，不进入普通三层主线。
- 编号卡包方向写入文档：后续优先使用 `common_1`、`common_2`、`sword_1` 等包名，不用基础 / 进阶 / 高阶暗示强弱。

## 2026-07-07：早期难度曲线二次回调

- 第二、三层敌方基础成长重新压低：第二层主要增加少量生命和攻击，第三层开始明显抬高生命并接入普通敌方牌包，但不再让普通敌人过早获得防御。
- 精英 / 首领的额外防御继续延后到后续劫数或通关后挑战中出现，前三层先让低分卡和基础攻击保持有效，避免早期剑修和通用低分卡被防御硬卡。
- 第三层普通 / 精英敌方牌包减少直接伤害密度，改为以 `破甲符`、`缚身符`、`铁木甲` 和少量 `金刃符` 表达压力。
- 第三层首领牌包暂不使用 `雷击符` 这类大额直接伤害，改为削弱 / 装备 / 少量伤害；强力敌方攻击牌等敌方延迟或放置牌机制成熟后再回到中低层 Boss。
- 无局外成长压力测试结果从“第三层 0% 通过”回调为后续继续观察目标；第三层仍应明显变难，但不应成为纯数值硬墙。

- 增加回归测试，覆盖敌方阵营出牌不会因为场上有多个敌方单位而变成每单位各出 1 张。

## 2026-07-07：阵营牌手与单位概念文档校正

- 明确战斗抽象只有我方阵营和敌方阵营两个牌手；场上单位不是独立牌手，没有自己的完整回合、牌库或卡组。
- 明确单位只是阵营控制的战斗对象，承载生命、攻击、防御、装备、状态、资源和基础行动额度。
- 明确失败条件差异：我方主单位死亡则战败；敌方场上单位全部死亡则胜利。
- 明确职业本质是开局默认主单位和卡池解锁来源；剑修、符修等职业卡后续应通过 `unit_id`、`unit_tags` 等稳定字段限制目标或使用者。
- 明确卡牌检索和字段解锁只看数据字段，不扫描卡面效果说明文本；文档中旧“玩家”描述后续要迁移为“我方主单位”或“我方阵营”。
