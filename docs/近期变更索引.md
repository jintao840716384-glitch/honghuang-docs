# 近期变更索引

本文只保留最近 5-10 条当前状态变化索引。每条只写当前结果，不写原因、过程、旧方案对比或验证长输出。
超过 10 条时，删除最早且已被核心文档吸收的条目。近期变更索引不归档旧条目。

## 2026-07-10：P0 包体与文档闭合

- `DataRegistry/DataValidator`、`WorldDifficultyDatabase`、`DifficultyCurveDatabase`、`MapContentDatabase`、`BattleContext/Request/Result`、Snapshot/ViewModel 与 `SaveStore` 是当前正式边界；效果、目标、去向、难度曲线、地图、资源、本地化和跨数据引用由生产启动统一校验。
- 出牌、目标、攻防、回合、响应和装备替换统一返回 BattleResult；BattleContext 只保存单场状态，BattleUI 与 EnemyAIController 只消费各自 Snapshot。
- 视觉、音频和六个正式界面本地化使用当前代码 canonical id / key 与明确 fallback；CardDatabase 仅转发定义、池和实例，DeckBuildRules 独占构筑规则。

## 2026-07-10：active 卡牌 EffectStep 闭合

- 8 张 active 卡牌统一使用逐卡 `content_state` 和 `effect_steps[].effect_type`；`EffectResolver` 解释通用效果，`CardResolver` 保留发动编排、目标/条件校验、来源卡去向和请求衔接。

## 2026-07-10：四 active 状态独立实例

- `StatusDatabase` 承载 `poison`、`armor_break`、`weak`、`next_damage_reduce` 四个 active 英文 ID；`BattleUnit.status_instances` 是唯一运行容器，同名实例独立并按创建顺序结算与清除。

## 2026-07-10：职业作用域 active 成长轨道

- `ProgressionDatabase` 以 `(job_id, progression_id)` 承载 13 个 active 短 ID 定义；版本 2 的 `jobs[job_id].upgrades[progression_id]`、现有消耗和 bonus 保持不变。

## 2026-07-10：canonical 事件定义与选择链

- `EventDatabase` 承载 `event_windfall_01`、`event_trade_01`、`event_minor_01` 三个 active 定义，权重为 8、30、62；正式地图事件传递 canonical `event_id`。

## 2026-07-10：敌方牌包模板 canonical
