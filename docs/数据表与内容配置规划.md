# 数据表与内容配置规划

## 当前状态

当前卡牌、职业、敌人数据仍写在 GDScript 数据类中，适合 Demo 快速试错。等玩法稳定后，应逐步拆成更适合维护的数据配置。

## 未来建议拆分

### 职业数据

- 职业 id。
- 名称。
- 初始生命。
- 基础攻击。
- 基础防御。
- 初始牌组。
- 专属资源。
- 职业说明。

### 卡牌数据

- 卡牌 id。
- 名称。
- 类型。
- 标签。
- 描述。
- 费用。
- 触发时点。
- 使用后去向。
- 效果参数。
- 稀有度。
- 职业归属。
- 升级版本。

### 敌人数据

- 敌人 id。
- 名称。
- 生命。
- 攻击。
- 防御。
- 行动序列。
- 意图显示。
- 节点类型修正。
- 精英或首领变体。

### 探索节点数据

- 节点类型。
- 层数。
- 可连接节点。
- 权重。
- 事件池。
- 奖励池。

### 奖励数据

- 卡牌奖励池。
- 职业限定奖励。
- 节点类型奖励修正。
- 精英奖励。
- 首领奖励。

### 后续系统数据

- 遗物。
- 商店商品。
- 事件。
- 卡牌升级。
- 状态效果。
- Buff / Debuff。

## 当前建议

Demo 阶段先不要急着拆成大量外部表。等卡牌数量、敌人数量和节点类型开始明显增加时，再迁移到 JSON、CSV 或 Godot Resource。

短期优先级：

1. 保持当前数据类可读。
2. 新增内容时维持字段一致。
3. 在文档里先记录字段规划。
4. 重构前再统一迁移数据格式。
