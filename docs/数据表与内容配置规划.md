# 数据表与内容配置规划

## 当前状态

当前卡牌、职业、敌人、地图和事件数据仍写在 GDScript 中。Demo 阶段先保持这种方式，方便快速试卡和调数值。

等卡牌和敌人数量明显增加后，再考虑迁移到 JSON、CSV 或 Godot Resource。

## 卡牌字段

当前新增或调整卡牌时，优先保持这些字段一致：

- `id`：卡牌 id。
- `name`：显示名称。
- `type`：`spell` 或 `defense`。
- `build_cost`：卡牌分数，只用于卡组总分和奖励过滤，不是出牌费用。
- `tags`：职业、功能和类型标签。
- `search_tags`：卡牌检索、卡包筛选和字段解锁使用的规则标签；不要从效果说明文本中反向解析检索字段。
- `description`：卡面描述。
- `trigger_timing`：防御牌可响应的时点。
- `response_target`：响应目标范围，例如我方主单位或我方单位。
- `effect`：当前旧式效果或效果组合。
- `effect_steps`：后续优先扩展的通用效果步骤。
- `after_use`：使用后去向，例如墓地、除外、放置区或装备区。
- `target_requirements`：可选，用于限制目标单位或使用者，例如需要目标拥有 `剑修`、`符修`、`主单位` 等稳定字段。
- `shop_price`：可选，覆盖默认坊市价格。
- `unlock_tier`：旧卡池解锁层级，当前作为兼容字段保留。0 对应第一批编号包，1 对应第二批，2 对应第三批。
- `unlock_pack`：卡牌主要所属解锁包名。当前使用 `common_1`、`common_2`、`sword_1`、`talisman_1` 等编号包，不用基础 / 进阶 / 高阶暗示强弱。
- `unlock_packs`：卡牌可属于的解锁包数组。当前大多数卡只有 1 个包，后续可用于同一张卡被多个包或活动来源解锁。
- `default_unlocked`：是否开局默认进入奖励和商店来源。
- 当前代码中 `CARD_UNLOCK_PACKS` 是已实现卡牌的显式包表；旧 `CARD_UNLOCK_TIERS` 只作为兼容 fallback，避免老字段失效。

当前不配置同名数量上限。

当前不做属性或五行克制字段。金、木、水、火、土等字可以先留在卡名或标签风味中，但不触发额外规则。

伤害步骤默认受目标防御力减免。只有明确配置 `ignore_defense = true` 的效果才无视防御，卡面描述也必须写清“无视防御”。

## 效果与技能数据

卡牌、敌人技能、首领技能和召唤物行动应尽量描述为效果步骤。

通用效果步骤优先覆盖：

- 伤害。
- 治疗。
- 攻击变化。
- 防御变化。
- 抽牌。
- 检索。
- 回收。
- 下一次基础攻击变形，例如全体、多段或伤害倍率。
- 放置。
- 装备。
- 召唤。
- 资源计数器变化。
- 状态计数器变化。
- 触发次数或冷却。

如果一个效果只服务单张卡，先不要急着硬写新系统。等至少几张卡或几个敌人都需要同类能力时，再抽成通用模块。

## 战斗单位数据

我方默认主单位、敌人、召唤物和未来法宝单位应共用战斗单位字段。单位不是独立牌手，也没有自己的卡组；单位只是场上的战斗对象，由所属阵营牌手控制。

- 单位 id。
- 显示名称。
- 阵营。
- 单位类型。
- 单位标签，例如 `主单位`、`剑修`、`符修`、`召唤物`、`首领`。
- 规则名称或稳定 id，用于卡牌限制和检索；显示名称只给 UI 使用，不参与规则判断。
- 站位槽。
- 最大生命和当前生命。
- 攻击。
- 防御。
- 状态计数器。
- 资源计数器。
- 装备槽数量。
- 已装备卡。
- 存活、退场、不可选中等标记。
- 自动行动或技能列表。

装备槽当前按单位阶级决定：

- 普通单位 1 槽。
- 精英单位 2 槽。
- 首领单位 3 槽。
- 我方主单位 2 槽。

## 角色池、敌方卡组与遭遇数据

当前敌方遭遇底座已从 `EnemyDatabase.gd` 拆为四块：`CharacterDatabase.gd` 管通用角色池，`EnemyDeckTemplateDatabase.gd` 管敌方卡组模板池，`DifficultyCurveDatabase.gd` 管难度曲线，`EncounterFactory.gd` 负责把三者组装成战斗遭遇。`BattleEncounterRuntime.gd` 再把遭遇数据适配为战斗运行期需要的主敌人、敌方牌组 profile、抽牌数和出牌额度；`EnemyDatabase.gd` 暂时保留为兼容门面，维持旧入口不变。这里的“角色”是通用战斗单位模板，不只指敌人；我方可选主单位、敌人、Boss、召唤物和未来法宝单位都可以从角色池取基础模板。

玩家可选角色可以进入角色池，但“可局外成长、初始牌组、职业卡池”等玩家侧包装仍由 `JobDatabase` / `MetaProgression` 管理，不直接塞进角色池。当前 `JobDatabase.gd` 已通过 `character_id` 引用 `CharacterDatabase.gd` 中的玩家主单位模板，继续向外兼容返回生命、攻击、防御和标签字段。

角色池只描述“这个单位是谁”，不要把整场遭遇写死在单位上。普通、精英和首领的差异优先放在敌方卡组模板、敌方阵营抽牌数和难度曲线中，而不是给每个单位写独立出牌流程。

角色模板字段：

- 角色 id。
- 名称。
- 基础生命。
- 攻击。
- 防御。
- 标签。
- 默认行动序列。
- 技能列表。
- 状态和资源初始值。
- 装备槽覆盖。
- 未来动画 / 角色资源占位 id。

敌方卡组模板字段：

- 卡组模板 id。
- 遭遇类型：普通、精英、首领。
- 主线层数：当前标准主线为 1 到 3 层；隐藏 Boss、完整牌手对手和 Boss 连战不写入普通层数。
- 敌方卡组列表。
- 可引用角色列表：引用角色池 id，可覆盖站位、生命 / 攻击 / 防御微调。这里是卡组模板引用角色，不是角色反向绑定卡组。
- 敌方阵营抽牌数。
- 敌方起始手牌数。普通、精英和非终极首领默认起手 0；终极 Boss 后续可例外使用接近玩家的起手规则。
- 敌方放置区和装备区规则。
- 主题标签。
- 世界难度下的卡组替换入口。
- AI 行动偏好。

敌方卡组长期方向是阵营级卡组：敌方阵营按普通 / 精英 / 首领配置不同抽牌数和模板，不是每个敌方单位各自拥有牌库。普通敌人建议每回合抽 1，精英抽 2，首领抽 3；终极 Boss 可以例外接近玩家完整规则。

敌方卡组模板可以突破玩家卡组下限，普通和精英建议 3 到 5 张。模板内容固定，遭遇生成时从该层该等级的若干卡组模板中选一套，再由这套模板引用角色池生成敌方单位；不要每场临时随机拼卡，也不要先选角色再倒推卡组。普通敌人每层可以先 2 到 3 套，精英每层至少 2 套，后续扩到 3 套。Boss 倾向每层至少 3 套，对应未来不同 Boss 角色 / 动画占位。

当前实现为：每层普通 / 精英 / 首领都已经走敌方卡组模板池；第一层普通和精英世界难度 0 仍多为空牌包，第一层首领有 3 套 5 张轻牌包；第二层精英有 3 套 3-4 张模板，第二层首领有 3 套 6 张牌包；第三层普通有 3 套 3 张模板，第三层精英有 3 套 4 张模板，第三层首领有 3 套 7 张牌包。

难度曲线独立于角色模板和卡组模板。战斗开始前根据主线层数、地图节点位置、遭遇类型和 `world_difficulty` 计算生命 / 攻击 / 防御修正，再叠加到角色模板上。生命成长最快，攻击其次，防御成长最慢且保持稀有。普通、精英和首领使用不同曲线；Boss 单独曲线暂不拆，后续如需要再扩展。

敌方阵营当前会在单位基础行动队列前统一尝试出牌，出牌上限暂按该遭遇抽牌数计算。敌方主动牌目前只使用伤害、削弱和轻装备这类可自动选择目标的牌。敌方放置牌、盖伏响应牌、检索牌和复杂召唤牌后续再接，避免在 UI 暂不显示敌方手牌时引入难解释的时点和选择流程。

## 探索与经济数据

探索节点字段：

- 节点 id。
- 节点类型。
- 地图排数。
- 主线层数，当前为三层主线中的第几层。
- 可连接节点。
- 权重。
- 事件池。
- 奖励池。
- 商店库存池。
- 修为点奖励。

奖励字段：

- 普通战斗奖励池。
- 精英战斗奖励池。
- 首领战斗奖励池。
- 通用卡池。
- 职业卡池。
- 卡池解锁层级。
- 编号卡包，例如 `common_1`、`common_2`、`sword_1`、`sword_2`。
- 当前 UI 预留通用 1-5 和当前职业 1-5 的卡包槽位；槽位用于显示和后续扩充，不代表正式流程会默认开放全部卡包。
- 默认开放 `common_1` 和当前职业的 `职业_1`；旧 `card_unlock_tier` 每提升 1 级，向后开放一批通用和职业编号包。
- 遭遇类型分数段过滤后如果候选少于 3 张，会在同一已解锁卡包范围内放宽分数下限，保证奖励三选一有基本选择面。
- 奖励落点：当前卡组或备牌区。
- 第一、二层首领后进入下一层地图；第三层首领后结算本轮修为点，不再进入局内突破升级三选一。
- 中途战败返回菜单前也结算已完成节点的修为点；当前战败节点未完成，不计入本轮基础修为。

局外成长字段：

- 职业 id。
- 累计修为点。
- 已花费修为点。
- 成长项等级。
- 成长项定义与价格表。当前由 `ProgressionDatabase.gd` 维护，价格按三层主线收益重标定，后续调奖励或节点数量时需要同步复查。
- 当前卡池解锁层级。
- 当前称号阈值。当前由 `ProgressionDatabase.gd` 维护。
- 已解锁编号卡包。
- 后续预留劫数等级、隐藏 Boss 解锁条件和卡牌屏蔽槽。
- 存档路径当前为 `user://progression.json`。

坊市字段：

- 商品位数量，当前 6。
- 商品池。
- 刷新费用。
- 单个坊市内刷新费用递增。
- 购买价格。
- 出售价格。

事件字段：

- 事件类型。
- 奖励内容。
- 代价类型。
- 可选项展示文本。

## 基础配置数据

基础配置不是玩法内容，但同样要求唯一来源，避免每个界面自行保存或解释。

设置字段当前由 `GameSettings.gd` 定义并清洗：

- 显示：分辨率 id、窗口模式、垂直同步。
- 音频：主音量、音乐音量、音效音量。
- 玩法：动画速度。
- 辅助功能：减少动态效果、减少闪烁、文本缩放。
- 本地化：当前语言 id。
- 输入：按动作 id 存储的绑定配置。

显示档位由 `DisplayModeManager.gd` 维护。当前只支持 16:9 常见档位：1280x720、1600x900、1920x1080、2560x1440、3840x2160；基准为 1920x1080，缩放策略为等比留黑。

输入动作由 `InputActionDatabase.gd` 维护。功能代码应读取动作名，例如 `end_turn`、`open_deck`、`hand_0`，不要读取具体键位；具体键位由设置页通过 `SettingsStore.gd` 写入 `input.bindings`，再由 `InputSettings.gd` 应用到 `InputMap`。当前支持每个动作一个键盘主绑定和恢复默认，鼠标 / 手柄绑定与冲突提示后续再扩。

文本本地化由 `LocalizationDatabase.gd` 和 `LocalizationService.gd` 维护：

- 语言 id，例如 `zh_cn`、`en_us`。
- 文本 id，例如 `menu.start_game`、`settings.master_volume`。
- 各语言文本。
- 参数占位，例如 `{percent}`。
- 缺失文本 fallback：缺失语言回退到默认中文，缺失 text id 返回 text id 本身，方便测试发现。

当前只接入主菜单和设置页第一批文案。后续迁移战斗、地图、事件、卡牌描述或教程文本时，应逐步给稳定文本分配 text id，不要从 UI 场景里复制长期硬编码文本。

素材授权记录由 `AssetAttributionDatabase.gd` 维护。正式素材需要记录资源 id、来源、作者、授权类型和商用许可状态；未知授权素材不能作为正式发布资产。

存档版本和旧字段迁移由 `SaveMigrationService.gd` 维护：

- 设置存档类型：`settings`，当前写入 `user://settings.cfg` 的 `_meta.schema_version`。
- 局外成长存档类型：`meta_progression`，当前写入 `user://progression.json` 的 `version`。
- 读取旧存档时先迁移和清洗，再交给设置或局外成长仓库使用。
- 后续新增收藏、图鉴、成就、设置扩展或局外成长字段时，先更新 schema 版本和迁移逻辑，不在 UI 或运行流程里临时修旧字段。

## 当前实现入口

- `CardDefinitionDatabase.gd`：卡牌定义、卡牌类型常量、卡面字段和基础分数读取。
- `CardDatabase.gd`：卡牌实例创建、旧兼容入口和解锁元数据补齐。
- `CardPoolDatabase.gd`：编号卡包、通用 / 职业卡池、奖励池过滤、随机奖励卡、商店库存和买卖价格，直接读取 `CardDefinitionDatabase.gd`。
- `DeckBuildRules.gd`：卡组张数、卡组总分上限、加卡阻塞原因和构筑合法性。
- `RewardService.gd`：战斗奖励、宝箱 / 事件卡牌来源和奖励数值；卡牌来源转发给 `CardPoolDatabase.gd`，节点修为奖励入口仅作为兼容转发。
- `CardAcquisitionRules.gd`：获得卡牌后的合法性检查、进入当前卡组或备牌区、结果消息；奖励、商店、事件和战斗奖励共用。
- `ShopService.gd`：坊市库存、价格、刷新费用、购买和出售规则。
- `EventService.gd`：事件种类、普通事件 / 奇遇 / 交易事件的选项、代价收益候选和事件结果计算。
- `ExplorationRules.gd`：节点修为奖励、节点完成收益、休息恢复结果和探索结算数值。
- `ProgressionDatabase.gd`：成长项定义、价格、分类、加成字段、称号阈值和层倍率。
- `MetaProgression.gd`：职业局外成长存档、修为点、成长等级、购买逻辑和当前加成汇总；旧成长定义入口暂时兼容转发。
- `CharacterDatabase.gd`：通用角色池和单位基础模板。
- `EnemyDeckTemplateDatabase.gd`：敌方卡组模板池。
- `DifficultyCurveDatabase.gd`：遭遇数值修正曲线。
- `EncounterFactory.gd`：把角色、敌方卡组模板和难度曲线组装为战斗遭遇。
- `BattleEncounterRuntime.gd`：把遭遇数据适配为战斗运行期入口。
- `EnemyDatabase.gd`：旧接口兼容门面。
- `JobDatabase.gd`：职业包装、`character_id`、初始牌组和职业说明；基础单位模板来自 `CharacterDatabase.gd`。
- `RunState.gd`：探索状态、卡组和备牌区；构筑合法性转发给 `DeckBuildRules.gd`，奖励来源转发给 `RewardService.gd`，入卡去向转发给 `CardAcquisitionRules.gd`，坊市规则转发给 `ShopService.gd`，事件选项和事件结果转发给 `EventService.gd`，节点完成、休息和探索结算转发给 `ExplorationRules.gd`；战斗启动 payload、战斗回流和放弃探索通过统一入口提交状态。
- `MapGenerator.gd`：地图节点生成。
- `EffectResolver.gd`：通用效果步骤。
- `GameSettings.gd`：设置默认值和清洗。
- `SettingsStore.gd`：设置文件读写和局部设置更新。
- `DisplayModeManager.gd`：分辨率档、窗口模式、垂直同步和等比留黑应用。
- `InputActionDatabase.gd`：输入动作定义、默认绑定、按键事件转换和绑定显示。
- `InputSettings.gd`：输入绑定读取、应用、fallback、单动作绑定和恢复默认。
- `LocalizationDatabase.gd`：语言定义、文本 id、中文 / 英文文本和缺失回退。
- `LocalizationService.gd`：按设置读取文本、参数替换和语言 id 解析。
- `SaveMigrationService.gd`：存档 schema 版本、设置迁移和局外成长迁移。
- `AssetAttributionDatabase.gd`：素材来源和商用授权登记。

## 短期内容扩展建议

1. 先在 `CardDefinitionDatabase.gd` 内补第一批卡。
2. 新卡尽量使用现有效果步骤或旧式效果入口。
3. 如果新增效果不能复用，优先补 `EffectResolver.gd` 的通用步骤。
4. 敌人先用少量明确动作和轻牌包验证趣味性。
5. 敌方卡组继续复用 `BattleSide` 和统一时点，不要另写一套平行技能系统。
## 素材资源配置

- 视觉素材不直接写进卡牌、角色、敌方卡组、战斗规则或 UI 流程脚本。
- UI 背景、静态场景图、角色精灵、战斗动画、图标和 VFX 统一登记到 `VisualAssetDatabase.gd`。
- 角色和敌方只引用 `visual_profile_id` / `animation_profile`；头像、战斗精灵、默认动画和图标由 `CharacterVisualDatabase.gd` 解释。
- 战斗事件到视觉表现动作的映射由 `BattlePresentationRouter.gd` 维护；具体播放节点、Tween、粒子或序列帧适配后续再接入。
- 音效、音乐、环境声和语音事件统一登记到 `AudioEventDatabase.gd`；播放和占位音频生成由 `AudioManager.gd` 负责。
- 背景音乐播放由 `MusicManager.gd` 负责，音乐事件和路径仍来自 `AudioEventDatabase.gd`。
- 真实素材文件放入 `assets/visual/` 或 `assets/audio/` 对应分区后，再绑定到数据库 id，并同步登记到 `AssetAttributionDatabase.gd`。
