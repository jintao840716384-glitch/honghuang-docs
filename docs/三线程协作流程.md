# 三线程协作流程

## 1. 权威依据与闭环

项目采用“总设计师、执行、验证”三线程连续闭环制。

三个线程只以 `README.md` 指定的六个核心文档、当前正式任务单和当前有效交接包为依据，不依赖旧对话历史或已被替换的方案。核心文档只记录当前有效状态。

每个完整里程碑默认只进行：一次执行前预审、一次连续执行、一次最终复核；需要补正时，最多再进行一次集中补正和一次补正确认。通过后立即封口，已封口里程碑不得自动重开。

## 3. 线程职责

### 总设计师

- 与用户确认里程碑、规则边界和必须由用户决定的事项。
- 一次性下发目标、范围包络、不可变约束、验收标准、验证矩阵和硬阻塞。
- 接收最终结论并向用户汇报；没有新目标时不继续派生工作。

### 执行线程

- 只执行通过预审的完整里程碑。
- 在范围包络内连续完成实现、文档同步、定向验证和普通技术修复。
- 完成后一次性提交压缩报告并转交验证线程。

### 验证线程

- 执行一次只读预审和一次最终复核；若集中补正，只再做一次补正确认。
- 只核对原目标、直接影响面、测试和工作树，不直接修改项目。
- 不得新增需求、扩大口径、重新扫描全仓或把无关问题升级为当前任务。

## 4. 完整里程碑任务单

任务单只保留六项：

1. 目标与完成定义。
2. 范围包络。
3. 不可变约束与禁止项。
4. 验收标准。
5. 验证矩阵及允许的环境替代方案。
6. 硬阻塞。

Git 提交、推送、备份等写操作必须单独授权；未授权时默认禁止。

等级只决定验证深度，不用于拆分：A 为文档或单点轻量改动，B 为标准数据或模块改动，C 为跨流程完整闭环，D 为只读审计或定向专项。未声明时默认 B。

## 5. 执行前预审

验证线程只预审一次，检查目标、范围、禁止项、验证矩阵和硬阻塞是否明确，是否存在必须由用户决定的玩法、数值、存档、active 内容或互斥路线，以及是否会形成第二套正式定义、长期兼容层或不可安全回滚风险。

结论只使用：`可执行`、`有技术条件可执行`、`需用户决策`、`不可执行`。

技术条件必须并入同一任务单；`需用户决策`、`不可执行`或命中硬阻塞时返回总设计师，其余情况直接进入执行。

## 6. 连续执行与硬阻塞

预审通过后，执行线程在同一个任务中连续完成实现、文档同步、测试、范围内修复和收口。

禁止按文件、子系统、审计、迁移计划、文档或测试轮次拆成独立阶段，也禁止为同一里程碑建立平行执行任务。内部计划和依赖顺序只是执行清单，不构成新阶段。

普通技术问题由执行线程在范围内自行解决，包括类型与接口问题、必要依赖适配、helper、文件组织、测试夹具、数据校验、当前状态文档同步和本次改动直接引起的测试失败。

只有以下情况属于硬阻塞：

- 必须改变玩家可见玩法、数值、概率、奖励或内容语义。
- 必须迁移存档结构或执行不可逆操作。
- 必须明显超出范围包络。
- 核心要求无法同时满足或核心文档直接冲突。
- 指定验证失败且无法在范围内修复。
- 存在数据损坏或不可安全回滚风险。

## 7. 最终复核与集中补正

执行完成后，验证线程进行一次最终复核。

若存在原范围内缺口，必须一次性汇总并退回原执行任务；不得分批发现、逐项退回或借补正开放新范围。执行线程完成集中补正后，验证线程只再进行一次补正确认，不得出现第三轮。

最终结论只使用：

- `通过`：范围内全部验收项满足，可以关闭里程碑。
- `不通过`：命中硬阻塞，或无法在原授权范围内闭合。

范围内有未完成项时不得通过。范围外且不阻塞的残余风险可以记录，但不得自动立项、阻止封口或附加到当前任务继续施工。

## 8. 完成即停止

通过后，总设计师只做里程碑关闭和用户汇报。三个线程均不得自动起草下一任务、重新扫描全仓、重开已封口专项、继续追求理想架构、清理无关技术债或执行未授权 Git 写操作。

后续工作必须等待新的明确目标。

## 9. 范围包络与工作树归因

范围包络按“目标系统、必要直接依赖、允许文件类别、禁止领域”定义。执行线程可以处理完成目标必需的直接调用方、消费者、数据库、Rules、Resolver、Service、Manager、helper、测试和当前状态文档，不得借此改动未授权的相邻玩法、数值、存档、目录结构或其他系统。

任务开始和结束记录 `git status --short` 或可复核摘要，并列出实际变更文件。只有在历史脏状态、高风险禁止文件或精确归因需要时保存哈希。

历史脏状态只作基线，不归因于当前任务，也不得被清理或回退。

## 10. 验证边界与吞吐限制

验证要求在任务单中一次确定，并与风险匹配：文档任务使用定向搜索和结构检查；数据或模块任务使用专项测试；正式流程、UI、战斗或存档任务使用覆盖对应入口的 smoke、flow、layout 或必要 probe。

Godot UI 任务默认使用 `tools/capture_visuals.ps1` 通过非 headless Viewport 捕获；修改前后主动捕获同一目标界面，并保持相同 screen selector、分辨率和 setup。正常流程不依赖用户截图，不使用 Computer Use 的 Godot 窗口捕获路径，不接受 `0x80004002` 作为替代结果，也不打开项目管理器或多个交互窗口。视觉探针用于可复核渲染基线，不替代人工交互验收。

默认上限：

- 全仓扫描最多 1 次，且仅在任务确实需要时执行。
- 执行前预审 1 次。
- 连续执行 1 次。
- 集中补正最多 1 次。
- 最终完整验证最多 1 轮。
- Probe 最多 1 次，且仅在数值、AI 或战斗结果可能变化时运行。
- 中途只运行与当前改动直接相关的定向测试。

若集中补正，只重跑失败项和直接受影响项；只有补正改变共享正式入口时，才允许重跑对应完整验证组，不得重复未受影响验证。

除非出现明确失败，不得重复全仓扫描或完整测试。

验证线程只能核对已声明目标和必要直接影响，不得新增功能、提高数值标准、要求无关重构或重开已封口专项。未运行的验证不得写成通过；环境失败必须与项目失败分开记录。

## 11. 报告压缩

执行期间只发送必要短状态。执行报告只保留目标结果、修改文件或类别、测试结论、工作树差异、硬阻塞和残余风险。

通过时，总设计师只汇报结论、完成内容、测试、残余风险和是否允许进入下一里程碑。只有不通过、测试异常、数据损坏风险或需要用户决策时才输出长报告。

## 12. 模型、推理强度与速度

模型、推理强度和速度由用户在客户端手动控制，属于项目外部运行参数，不属于任务单、预审、验收标准或线程自动管理范围。

- 以用户当前客户端设置为准。
- 三个线程不得自行要求升档、降档、切换模型或改变速度。
- 不得因为无法读取运行参数而暂停、重启、重复任务或降低验收标准。
- 只有涉及不可逆迁移、存档损坏风险或重大互斥路线时，总设计师可以提供一次建议；是否调整完全由用户决定。
- 用户未要求时，报告和交接包不重复记录运行参数。

## 13. 每角色唯一活动线程

总设计师、执行、验证各自只能有一个活动线程，一个线程只能承担一个角色。

不得保留临时代理与正式线程并行，也不得让旧、新线程同时接收任务。新线程确认接管后，旧线程立即归档。

额度不足或平台故障时，只能等待恢复或执行正式轮换，不得创建并行临时代理。

## 14. 上下文轮换与交接

总设计师负责管理三个角色的上下文轮换；总设计师自身轮换由用户确认。

达到约 85%：进入交接准备状态，不再接收新的大型里程碑。若剩余工作可在当前窗口安全完成，则完成当前里程碑；否则到达最近安全交接点后交接。

达到或超过约 90%：完成当前不可中断命令或最小原子操作后强制轮换，停止新的读取、实现和扩项，不得承接下一项正式任务，也不得因轮换重复扫描、测试或执行已完成工作。

自动上下文压缩本身不触发轮换。只有压缩后出现目标或边界遗漏、重复询问已拍板问题、修改清单或测试事实丢失、错误引用旧方案、无法稳定履职时，才按高风险轮换处理。平台不显示比例时，不推测具体百分比。

最小交接包只包含：

- 当前角色和旧线程 ID；已建立接替线程时附接替线程 ID。
- 当前目标、范围包络、禁止项和硬阻塞。
- 已确认且不得重开的口径。
- 已修改文件、剩余事项和下一安全动作。
- 已运行验证、结果和仍需运行的命令。
- 开始与当前工作树摘要，以及无法归因的变化。

交接包不复制旧对话、过程日志、历史方案或已被核心文档吸收的说明。

接替线程必须阅读六个核心文档、当前任务单和交接包，复述自身角色和边界，确认接管当前任务而不是重新审计。

## 15. 线程 ID 轻量更新

线程轮换后的 ID 更新属于配置维护，不是新里程碑。

总设计师确认接替线程后，由执行线程只修改本文件第 2 节对应 ID 行；验证线程进行三个角色 ID 定向核对。若轮换的是执行线程，由接替执行线程完成该更新。

更新时直接覆盖旧 ID，不保留旧 ID、原因、轮换记录或上下文百分比；使用 UTF-8，执行 `git diff --check`，不运行 Godot，不同步近期变更索引，也不启动完整闭环。

## 16. Git 基线与写操作

线程可以提出基线保存方案，但方案本身不授予执行权限。

没有用户明确授权时，任何线程都不得执行 Git 写操作，包括暂存、提交、建标签、建分支、合并、变基、重置、检出覆盖、推送、拉取、清理工作树或创建项目备份。

`git status`、`git diff`、`git log` 和哈希核对等只读检查可以按任务单执行。

用户授权 Git 写操作时，任务单必须精确写明操作类型、文件范围、目标分支或远端和失败回滚边界。未写明的 Git 操作仍视为禁止。
