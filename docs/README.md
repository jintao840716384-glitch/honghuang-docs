# 太玄宗文档索引

`docs/` 只保存当前项目设定和当前协作规则。历史方案、旧交接、修改过程和被替换的设计不长期保存在文档中；需要追溯时使用 Git 历史。

## 默认阅读顺序

核心文档为本 README 与以下 5 个当前文档：

1. `三线程协作流程.md`
2. `游戏规则总纲.md`
3. `实现架构总纲.md`
4. `数据与内容总表.md`
5. `近期变更索引.md`

正常接手只读以上核心文档。除非任务单明确要求，不需要寻找旧交接摘要、历史说明或归档文档。

## 文档职责

- `三线程协作流程.md`：记录总设计师、执行线程、验证线程的职责、任务分级、验证分级和自动转交格式。
- `游戏规则总纲.md`：记录当前游戏规则和战斗交互契约，包括阵营牌手、单位、卡牌使用流程、状态、装备、探索、成长、奖励和商店规则。
- `实现架构总纲.md`：记录当前代码模块职责、数据流方向和禁止越权边界。
- `数据与内容总表.md`：记录当前活跃卡牌、职业初始牌组、敌方牌包、角色/单位、奖励/商店/事件来源和最新数值探针结果。
- `近期变更索引.md`：只记录最近 5-10 条当前状态变化索引，每条 1-2 行；不记录过程、原因、争论、旧方案、验证长输出。

## 维护原则

- 核心文档只记录当前有效设定、当前模块职责、当前活跃数据和当前协作流程。
- 仓库内核心文档始终使用固定文件名，不使用“最新版”“迭代版”“同步版”等临时文件名；外部对话生成的迭代文件，合并入仓库后统一覆盖为正式文件名。
- 不得写入聊天过程、旧方案对比、已删除功能说明、历史原因、迁移过程、上一轮修改过程、未来猜想。
- 设定变化时直接替换对应内容，不在核心文档内追加旧内容。
- 如果旧内容被替换，直接删除旧口径，只保留新口径。
- 需要追溯原因时使用 Git，不在 `docs/` 中补历史解释。
- 更早记录直接删除，不归档到 `docs/`。
- 每个概念只保留一个主文档解释，其他文档只短链接或短引用。
- 不创建 `_历史文档`，不保留旧交接摘要。
- 不把实现细节写进规则文档，不把规则口径散落到数据清单或 UI 文案中。
