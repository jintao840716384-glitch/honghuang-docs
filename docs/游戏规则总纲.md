# 游戏规则总纲

本文为当前有效规则设定。实现职责见 `实现架构总纲.md`；活跃卡牌、敌方牌包、数值和内容来源见 `数据与内容总表.md`。

## 分层优先级

规则按以下顺序判定，前者优先于后者：

1. 总体玩法模型。
2. 数据归属模型。
3. 探索、节点、结算、局外成长。
4. 战斗双方、单位、区域、胜负。
5. 卡牌定义、目标、发动、去向。
6. 时点、响应链、效果、状态、装备、死亡。
7. 敌方遭遇、世界难度、奖励来源。
8. 具体卡牌、敌人、事件、数值内容。

具体卡牌、敌人、事件和数值不得反向污染底层规则。

## 核心术语

- 阵营牌手：一方战斗控制主体，持有本场牌库、手牌、墓地、除外区、放置区、单位和控制器。
- 玩家阵营牌手：真人控制的阵营牌手。
- 敌方阵营牌手：AI 控制的阵营牌手。
- 控制器：决定阵营牌手行动的主体。玩家由真人控制，敌方由 AI 控制。
- 可选角色 / 职业：玩家开始探索时选择的身份包装，绑定主单位、固定初始牌组、职业卡池、局外成长和职业机制。
- 单位：阵营牌手场上的战斗实体，不是卡牌。
- 主单位：玩家所选角色 / 职业绑定的核心单位。玩家主单位死亡，玩家战败。
- 卡牌：统一卡牌数据库中的规则对象。
- 卡牌实例：某场战斗或某个区域中的具体卡牌对象。同一 `card_id` 可以存在多个实例。
- `card_id`：卡牌唯一规则标识。
- 卡名：玩家可见名称，也可被卡牌效果引用。
- 标签：用于职业、系列、类型、关键词和检索规则的分类字段。
- 原拥有者：卡牌在本场对局开始时所属阵营。
- 当前控制者：当前能使用、装备、操控或从该卡受益的阵营。
- 当前卡组：本轮探索进入战斗使用的玩家卡组。
- 备牌区：本轮探索中暂不进入当前卡组、可在地图调整时换入的卡牌集合。
- 构筑分：玩家卡组构筑强度限制，不是战斗内费用。
- 灵石：本轮探索内临时货币。
- 修为点：局外永久成长货币，探索结算后获得并按可选角色 / 职业保存。
- 世界难度：探索使用的挑战等级；当前正式内容仅 `wd0`。
- 节点：探索地图上的可进入位置。
- 战斗实例区域：单场战斗运行时生成的牌库、手牌、墓地、除外区、放置区、装备 / 附着物区和临时状态集合。
- 放置区：阵营牌手场上 5 个槽位，用于盖伏防御牌、承载永续卡和其他明确进入放置区的卡。
- 盖伏牌：以隐藏状态放置在放置区的防御牌或其他明确允许盖伏的卡。
- 装备 / 附着物：挂载在单位身上的持续对象，默认不占用放置区。
- 战斗事件：战斗流程中即将结算或已经发生的行动、效果、状态、区域变化或系统检查。
- 时点：战斗事件进入待结算状态时暴露出的可检查响应节点。
- 响应窗口：某时点存在合法响应来源时，等待控制器选择的窗口。
- 响应链：同一待响应对象上连续形成的卡牌 / 效果链节，按后发先至结算。
- 链节：响应链中的单个卡牌发动、效果发动或强制触发。
- 破坏：使场上对象离场，默认进入原拥有者墓地。
- 反制 / 无效：取消尚未结算的卡牌或效果链节。
- 解除 / 驱散：移除状态、装备、附着物、永续效果或持续效果。
- 状态实例：单位身上独立记录来源、数值、计数、触发事件和移除条件的状态对象。
- 状态标签：状态用于检索、清除、驱散和规则判断的分类标记。

## 总体玩法

当前模式为章节探索式卡牌战斗。

1. 玩家选择可选角色 / 职业。
2. 系统进入该角色 / 职业的探索前准备界面。
3. 玩家确认当前已开放的局外成长、职业卡池和探索前配置。
4. 系统按该角色 / 职业生成玩家主单位和固定初始牌组。
5. 玩家进入三层节点式探索。
6. 玩家根据地图连线，从每层底部向上选择相邻可达节点推进。
7. 每层最终节点为 Boss 战。
8. 击败本层 Boss 后进入下一层。
9. 击败第三层 Boss 后，本轮探索通关并进入结算。
10. 玩家主单位生命归零时，本轮探索失败并进入结算。
11. 结算获得修为点，用于该角色 / 职业的局外成长。

当前主线暂定 3 层，每层暂定 7 个节点。具体地图生成、节点数量和节点分布以数据与内容总表为准。

## 可选角色 / 职业模型

可选角色 / 职业是玩家开始探索时选择的身份包装，不等同于普通单位，也不等同于卡组。

每个可选角色 / 职业绑定：

- 主单位模板。
- 固定初始牌组。
- 职业专属卡池。
- 职业局外成长。
- 职业专属资源或机制。
- 职业显示信息。

玩家选择角色 / 职业后，系统根据该选择生成玩家主单位、当前初始牌组、可获得卡池和局外成长读取路径。

职业专属卡池规则：

- 探索奖励卡池由已解锁通用卡池 + 当前职业已解锁专属卡池组成。
- 未选择的其他职业专属卡池不进入本轮奖励、商店、事件或宝箱来源池。
- 职业专属卡可以声明职业限制、单位限制、标签限制或检索限制。
- 职业专属卡若要求特定主单位、特定职业标签或特定职业资源，必须在卡牌数据中明确声明。

职业专属机制可以包括起始资源、战斗中资源获取、职业标签检索、专属状态、专属成长项和专属卡池解锁。具体职业内容写入数据与内容总表。

## 探索前准备

每次探索开始前，玩家先选择可选角色 / 职业。

选择后进入该角色 / 职业的准备界面。准备界面可提供：

- 开始探索。
- 局外成长升级。
- 职业卡池 / 卡包解锁。
- 世界难度选择仅在存在两个及以上 active 难度时显示；当前不显示。
- 探索前卡池屏蔽。
- 角色信息和当前成长查看。

当前不开放开局自由构筑初始牌组。玩家点击开始探索后，系统按所选角色 / 职业的固定初始牌组生成当前卡组，并进入第一层地图。

探索前准备只处理局外永久配置和本轮开局配置，不直接修改战斗实例区域。

## 本轮探索内继承

本轮探索内，以下探索层内容随节点推进持续保存：

- 玩家主单位当前生命。
- 玩家主单位由局外成长、事件或明确跨节点效果改变后的探索层基础攻击、基础防御。
- 当前卡组。
- 备牌区。
- 灵石。
- 已获得卡牌。
- 已触发并明确声明跨节点持续的事件结果。

战斗结束不会自动回满生命。恢复生命只能来自卡牌、事件、休息或其他明确效果。

以下内容默认只属于单场战斗实例，不跨战斗保存：

- 本场手牌。
- 本场牌库。
- 本场墓地。
- 本场除外区。
- 本场放置区。
- 本场装备 / 附着物。
- 本场状态。
- 本场召唤单位。
- 本场临时攻击、防御、抽牌数、行动额度修正。
- 本场响应链、时点记录和临时规则。

只有文本明确写明跨战斗、跨节点或本轮探索持续时，某个效果才允许在战斗结束后保留。

本轮探索结束后，当前生命、当前卡组、备牌区、灵石、局内获得卡牌、局内状态和局内事件结果默认不继承。探索结束后只保存修为点、局外成长和永久解锁内容。

## 节点类型

节点类型包括：

- 普通战斗：基础战斗节点。胜利后获得卡牌三选一和少量灵石。
- 精英战斗：高难战斗节点。胜利后获得卡牌三选一和更多灵石。
- Boss 战：每层最终节点。胜利后进入下一层或完成本轮探索。
- 普通事件：低风险事件，提供较低奖励或基础选择。
- 高级事件：提供较高奖励，通常需要支付代价。代价可以是生命、灵石、卡牌、状态或其他局内资源。
- 奇遇事件：提供高级奖励，默认无代价。具体出现规则和内容由数据表决定。
- 宝箱：提供卡牌或其他局内奖励。
- 坊市：允许购买卡牌、出售备牌区卡牌、刷新商品。
- 休息：提供生命恢复或其他恢复类效果。

节点内部结算完成后，返回地图界面。只有回到地图且未进入下一个节点前，才能自由调整当前卡组和备牌区。

## 灵石和坊市

灵石是本轮探索内临时货币。

灵石来源包括战斗胜利、事件、宝箱和其他明确产生灵石的效果。

灵石用途包括坊市购买卡牌、坊市刷新商品、事件支付和其他局内交易。

坊市规则：

- 购买卡牌消耗灵石。
- 出售卡牌仅允许出售备牌区卡牌。
- 当前卡组中的卡不能直接出售，除非先在地图卡组调整中移入备牌区。
- 商品刷新消耗灵石。
- 同一坊市内刷新次数越多，刷新费用越高。
- 卡牌价格与构筑分和内容强度相关。
- 具体价格公式、出售比例和刷新费用写入数据与内容总表。

## 挑战结算和修为点

本轮探索在以下情况进入结算：

1. 玩家主单位生命归零。
2. 玩家击败第三层 Boss。

结算时，系统根据本轮完成节点计算基础修为点。

修为点来源包括普通战斗、精英战斗、Boss、事件和其他明确提供修为点的节点或效果。

节点收益层级：Boss 节点最高，精英节点高于普通节点，事件节点按事件等级提供收益。

最终修为点按以下结构计算：

`最终修为点 = 节点基础修为点总和 × 通关层数倍率 × 世界难度倍率`

具体节点分数、层数倍率、世界难度倍率和取整规则写入数据与内容总表。

灵石、当前卡组、备牌区、局内获得卡牌和局内状态不转化为永久内容，除非某个结算规则明确声明。

## 局外成长

局外成长按可选角色 / 职业独立保存。

修为点可用于解锁或提升：

- 最大生命。
- 攻击。
- 防御。
- 构筑分上限。
- 基础抽牌数。
- 职业专属起始资源。
- 职业专属机制强化。
- 职业专属卡池开放。
- 通用卡包开放层级。
- 奖励卡牌分数上限。
- 高分卡出现概率。
- 初始牌组相关扩展。
- 探索前卡池屏蔽能力。

卡池屏蔽：允许玩家在探索前临时屏蔽部分已解锁卡牌，使其不进入本轮奖励池。被屏蔽卡不等于删除，不影响数据库、职业解锁和永久解锁状态。

局外成长不直接继承上一轮探索获得的卡牌。

## 世界难度

当前正式流程仅有 `wd0` 为 active，探索固定使用该难度；准备界面不显示难度选择，遭遇也不接受 prototype 或 disabled 难度。

`wd1` 为 prototype，`wd2`、`wd3` 为 disabled，均不进入正式探索、遭遇或结算。当前不存在额外可选难度，因此局外存档不保存最高世界难度。

卡牌自身数据不因世界难度改变。后续只有在新的世界难度完整成为 active 内容后，才可同时开放对应选择、遭遇范围、数值曲线、结算倍率和保存边界。

## 敌方遭遇生成

战斗遭遇由以下因素共同决定：

- 遭遇类型。
- 地图层级。
- 节点序号。
- 世界难度。
- 敌方牌包模板开放范围。
- 敌方单位模板开放范围。

遭遇类型包括普通战、精英战、Boss 战。

敌方不参与玩家构筑系统。敌方没有当前卡组、备牌区、构筑分、探索中获得卡牌、卡组调整或保存合法性检查。

敌方牌库由开发者预设的敌方牌包模板直接生成。系统根据当前地图层级、节点序号、世界难度和遭遇类型开放候选范围，并从可用模板中随机选择一套作为本场敌方阵营牌手的基础牌库。

敌方牌包模板可以绑定允许出场的敌方单位范围。系统根据模板、层级、节点序号、遭遇类型和世界难度生成敌方单位数量与单位强度。

敌方单位基础面板来自单位模板。实际生命、攻击、防御可根据地图层级、节点序号、遭遇类型和世界难度进行加成。

敌方抽牌数量由敌方基础抽牌数、遭遇类型、地图层级和世界难度曲线共同决定。普通、精英、Boss 可以拥有不同抽牌曲线。具体曲线写入数据与内容总表。

## 卡组与备牌

当前玩家卡组模型是“当前卡组 + 备牌区”。构筑规则只作用于玩家。

- 当前卡组用于战斗。
- 备牌区用于探索中重构。
- 当前卡组最小 10 张。
- 当前卡组最大 20 张。
- 初始构筑分上限 20。
- 备牌区默认不设数量上限。
- 不限制同名卡数量。
- 不使用稀有度禁限。
- 不使用强制删牌式肉鸽逻辑。

获得卡牌时：

1. 系统优先尝试加入当前卡组。
2. 若加入后仍满足张数上限和构筑分上限，则进入当前卡组。
3. 若加入后会导致张数超限或构筑分超限，则自动进入备牌区。
4. 奖励结算时玩家不选择入卡位置。
5. 节点结算回到地图后，玩家可进入卡组调整。

若未来设置备牌区上限或特殊阻塞规则，获得卡牌时必须由入卡规则处理。

卡组调整采用“编辑副本 + 保存校验”模型：

- 只能在地图界面、未进入节点前调整。
- 战斗、事件、宝箱、坊市、休息节点内部不能自由调整。
- 编辑过程中允许临时非法。
- 保存时必须满足张数下限、张数上限、构筑分上限。
- 保存失败不改变当前有效卡组。
- 取消调整恢复进入编辑前的合法卡组。

## 奖励来源和活跃内容

奖励、商店、事件、宝箱只从当前玩家可获得来源池取卡。具体来源池以 `数据与内容总表.md` 为准。

当前玩家可获得来源池由以下内容组成：

- 已解锁通用卡池。
- 当前选择角色 / 职业已解锁专属卡池。
- 当前节点、事件、宝箱、坊市或奖励规则明确追加的临时来源池。

未选择的其他职业专属卡池不进入本轮奖励、商店、事件、宝箱或普通卡牌获得来源。

废卡默认不进入玩家奖励、坊市、事件、宝箱或职业包，除非某个内容明确设计为可获得负面卡。

卡牌奖励默认为三选一，玩家必须选择其中一张。当前不提供跳过奖励。

奖励生成时，系统从当前可获得来源池中过滤合法卡牌。若合法卡牌不足三张，则按实际合法数量展示；若没有合法候选，则按数据表指定兜底奖励处理。

## 战斗双方模型

一场战斗是两个阵营牌手对抗。

双方共用：

- 牌库、手牌、墓地、除外区、放置区。
- 装备 / 附着物。
- 抽牌规则、出牌规则、单位规则、状态规则。
- 效果结算规则、时点 / 响应规则。

双方差异来自：

- 控制主体不同：玩家由真人控制，敌方由 AI 控制。
- 起始配置不同：玩家有初始手牌，敌方默认无初始手牌。
- 牌库来源不同：玩家来自探索层当前卡组，敌方来自开发者预设敌方牌包模板。
- 成长与构筑不同：玩家拥有构筑、备牌、获得卡牌和局外成长；敌方不参与构筑系统。
- 胜负条件不同：玩家主单位死亡判负；敌方全部单位死亡判负。

敌方阵营牌手使用与玩家相同的战斗底层规则。

## 信息可见性

当前探索战中，玩家可见：

- 己方手牌。
- 己方战斗区域。
- 己方盖伏牌详情。
- 敌方场上单位。
- 敌方公开状态。
- 敌方公开装备 / 附着物。
- 敌方放置区槽位。
- 敌方已公开表侧放置卡。

敌方手牌、牌库、墓地、除外区和盖伏牌详情属于隐藏信息，默认不可查看，也不显示详情。

查看敌方隐藏信息必须由卡牌效果明确允许。

若卡牌效果要求从敌方隐藏区选择目标，必须先通过该效果公开、查看、随机选取或按规则指定目标。

敌方控制器默认只依据其可见信息行动。若某个敌人、世界难度或技能允许读取玩家隐藏信息，必须作为明确规则或敌方能力写入内容数据。

## 战斗开始

当前单人探索模式固定玩家先攻。

战斗开始时：

1. 双方按遭遇数据和运行状态生成单位。
2. 玩家按探索层当前卡组生成本场牌库。
3. 敌方按敌方牌包模板生成本场牌库。
4. 双方牌库洗牌。
5. 玩家阵营从牌库抽取 5 张作为初始手牌。
6. 敌方阵营默认没有初始手牌。
7. 进入玩家第一回合。

玩家初始 5 张手牌属于战斗初始化，不属于回合抽牌步骤，不消耗第一回合抽牌次数，不触发抽牌时点或响应窗口。玩家第一回合开始时，仍按正常抽卡步骤抽牌。

敌方从自身第一个回合开始，按自身抽牌数从 0 手牌开始抽牌。

## 战斗实例区域和战斗结束清理

战斗开始时，系统根据探索层当前卡组生成本场战斗牌库。本场牌库、手牌、墓地、除外区、放置区、装备 / 附着物区和状态集合都是战斗实例区域。

战斗中卡牌在牌库、手牌、墓地、除外区、放置区、装备 / 附着物区之间移动，只影响本场战斗实例，不直接改变探索层当前卡组或备牌区。

战斗结束后，本场战斗实例区域清空。手牌、牌库、墓地、除外区、放置区、装备 / 附着物区、战斗内状态、临时召唤单位和临时规则全部结束。

当前卡组本体不会因为本场战斗中的使用、弃置、除外、装备、破坏、进入墓地而改变。

只有获得卡牌、出售卡牌、删卡、事件改卡组、卡牌文本明确写明“加入当前卡组”“从当前卡组移除”“加入备牌区”“本轮探索持续”时，才修改探索层当前卡组或备牌区。

## 胜负条件

- 玩家主单位死亡，玩家阵营失败。
- 敌方全部单位死亡，敌方阵营失败。
- 玩家主单位死亡优先于敌方全灭胜利判定。
- 同一结算中玩家主单位死亡且敌方全部单位死亡，判定玩家战败。

## 单位模型

单位至少拥有：

- 生命。
- 最大生命。
- 攻击。
- 基础防御。
- 当前有效防御。
- 状态实例列表。
- 装备 / 附着物列表。
- 行动额度。
- 存活状态。

单位不是卡牌。单位离场不进入墓地。单位身上的状态、装备、附着物按各自规则处理。

## 召唤单位

召唤单位不是特殊单位类型。单位只要进入场上，就按普通单位规则处理。

召唤单位由卡牌、状态、事件或敌方技能把指定单位模板加入指定阵营场上。

召唤单位属于其控制者阵营。

玩家阵营召唤单位死亡，不导致玩家失败。玩家失败条件仍为玩家主单位死亡。

敌方阵营召唤单位属于敌方存活单位。敌方是否全灭，按场上所有敌方存活单位判断，包括召唤单位。

单位在所属阵营回合内被召唤到场时，默认获得 1 次基础行动额度。

单位在非所属阵营回合被召唤到场时，默认不立刻获得基础行动额度，直到其所属阵营下一个正式回合按正常规则刷新。

召唤单位默认只存在于本场战斗，不跨战斗继承。

卡牌文本可以明确声明召唤单位不能行动、立即行动、额外行动、不计入胜负或跨战斗持续。

## 牌手行动与单位行动

牌手在己方行动阶段可以：

- 控制己方有行动额度的单位进行普通攻击。
- 控制己方有行动额度的单位进行防御。
- 从手牌发动合法法术牌。
- 从手牌盖伏合法防御牌。
- 发动己方场上满足条件的卡牌或效果。
- 处理卡牌效果产生的目标选择。
- 结束回合。

单位拥有行动额度，但单位不会自行行动。单位行动由所属阵营牌手控制器提交。

每个存活单位在其所属阵营正式回合开始时获得 1 次基础行动额度。

单位基础行动额度可用于普通攻击或防御。

牌手可以不使用某个单位的行动额度并直接结束回合。未使用的行动额度在回合结束时清空。

普通攻击：选择敌方一个存活单位，按攻击力进行一次伤害结算。

防御：消耗 1 次基础行动额度，使单位进入防御姿态。

防御姿态规则：

- 默认使该单位基础防御翻倍。
- 持续到下一个己方正式回合开始前。
- 若单位基础防御为 0，则改为获得 1 点临时防御。
- 不永久改变单位基础防御。
- 单位进入防御姿态后，本回合不能再进行普通攻击。
- 即使之后通过卡牌、状态、装备或事件获得额外行动额度、额外攻击次数或恢复行动额度，也不能在本回合转为攻击，除非效果明确写明可以解除防御姿态并允许攻击。
- 当前有效防御翻倍属于特殊效果，只能由卡牌、状态、装备或敌人技能明确声明。

卡牌、状态、装备、事件可以增加、减少、恢复或消耗单位行动额度。额外行动额度仍走统一单位行动流程。

使用卡牌不消耗单位行动额度。单位攻击或防御不消耗出牌次数。当前不设通用每回合出牌次数上限。

## 回合流程

每个阵营回合按以下流程执行：

1. 抽卡步骤。
2. 正式回合开始。
3. 刷新本阵营单位行动额度。
4. 移除到期防御姿态和到期回合标记。
5. 回合开始效果结算步骤。
6. 行动阶段。
7. 回合结束前事件。
8. 回合结束清理。
9. 牌库重整检查。
10. 切换阵营。

抽卡步骤具有最高优先级。抽卡步骤完成前，不结算中毒、状态、永续卡、回合开始触发效果或其他卡牌效果。抽卡步骤完成后，才进入正式回合开始和回合开始效果结算步骤。

行动额度刷新、防御姿态到期和系统回合标记刷新属于系统流程，不属于卡牌效果，不打开响应窗口，除非某个规则明确声明。

## 抽牌、手牌和重整

双方手牌上限为 6。

每个阵营默认每回合抽 1 张。实际抽牌数可由局外成长、敌方模板、难度曲线、卡牌或状态修改。

抽牌采用尽量执行规则：

- 每抽 1 张时分别检查牌库和手牌空位。
- 牌库为空，该次抽牌失败。
- 手牌已满，该次抽牌失败。
- 未能抽取的数量直接损失。
- 不记录欠抽。
- 后续不补抽。
- 部分抽牌失败不回退已完成结算。

牌库重整规则：

- 回合结束清理时，若该阵营牌库为空，则将该阵营墓地洗回牌库，并清空墓地。
- 牌库不为空时，不进行墓地重整。
- 当前手牌不参与重整。
- 除外区不参与重整。

检索和定向取牌：

- 从牌库定向查看、选择、检索、拿取卡牌后，默认洗牌。
- 调整牌库顶 / 牌库底顺序类效果按卡牌文本优先，不被默认洗牌破坏。
- 检索目标需要加入手牌时，若手牌已满，该部分效果失败，被检索卡保持原区域。
- 效果来源按自身去向处理。

## 卡牌定义模型

卡牌是统一卡牌数据库中的规则对象，通过统一规则结算。

每张卡必须描述基础字段：

- `card_id`。
- 卡名。
- 卡牌类型。
- 构筑分。
- 标签。
- 来源卡包。
- 目标模式。
- 目标范围。
- 效果步骤。
- 使用后去向。
- 显示描述。

以下字段按需要声明；未声明时走默认规则：

- 持续属性。
- 发动方式。
- 发动区域。
- 发动事件。
- 发动条件。
- 触发条件。
- 是否留场。
- 是否装备 / 附着。
- 是否可被检索。
- 是否可在响应链中发动。
- 是否改变默认区域移动。

卡牌未写明的规则，使用默认规则。卡牌文本只声明自身需要改变、限制或追加的部分。

卡牌本身不分玩家卡或敌方卡。玩家和敌方通过同一套效果规则结算卡牌。差异来自来源限制、职业包、敌方牌包模板、控制器选择。

## 卡牌检索字段

卡牌默认可被检索。若某张卡不可被检索，必须由卡牌数据或卡牌文本明确声明。

检索效果只作用于符合检索条件且允许被检索的卡牌。

检索效果可以引用以下字段：

- 指定 `card_id`。
- 指定卡名。
- 卡名包含指定字段。
- 指定标签。
- 指定卡牌类型。
- 指定持续属性。
- 指定发动方式。
- 指定来源卡包。
- 指定构筑分范围。
- 指定区域。
- 指定原拥有者。
- 指定当前控制者。

检索文本必须明确检索区域。加入区域未写明时，默认加入手牌。若效果不是加入手牌，必须明确写明进入墓地、牌库顶、牌库底、放置区、装备区、除外区或直接发动。

## 卡牌目标模式

卡牌目标模式决定发动时是否取对象、由谁选择对象、哪些对象受影响。

基础目标模式：

- 无目标：发动时不选择目标，例如抽牌、自身除外、全局规则改变。
- 单目标：发动时选择 1 个合法目标。
- 多目标：发动时选择多个合法目标，数量由卡牌文本决定。
- 全体目标：不逐个选择，系统作用于全部符合条件对象。
- 随机目标：不由控制者选择，系统从合法对象中随机选取。
- 自身目标：作用于发动者、控制者、来源卡、装备对象或状态宿主。

可作为目标的对象由卡牌文本声明，包括但不限于：单位、区域中的卡、放置区卡、装备 / 附着物、状态实例。

“不能被选择为目标”只影响单目标和多目标。全体目标、随机目标、非取对象效果不受该类规则影响，除非文本明确说明。

## 卡牌分类

卡牌至少按三维理解。

基础类型：

- 法术牌：通常可在己方行动阶段从手牌主动发动。
- 防御牌：默认不能从手牌直接发动，必须先盖伏到放置区。

持续属性：

- 一次性：结算后按卡牌去向规则处理。
- 永续：卡牌文本明确写明留场，发动成功后保留在放置区持续生效。
- 装备：发动成功后装备到合法单位，保留卡牌身份并成为装备对象。
- 附着：发动成功后附着到合法对象，按文本提供持续、延迟或触发效果。

发动方式：

- 主动发动：控制者在合法时点主动使用。
- 可选触发：满足条件时，控制者可选择是否发动。
- 强制触发：满足条件时自动发动。

装备不是当前独立基础类型，默认作为法术牌或其他卡牌的持续属性处理。具体装备规则见“装备和附着物”。

永续和装备必须留在场上才能维持持续效果，并作为可被破坏、解除、弹回、除外、抢夺或转移的交互对象。

## 放置区、盖伏和永续

每个阵营牌手拥有 5 个放置区槽位。

放置区用于盖伏防御牌、承载已发动永续卡、承载明确写明进入放置区的其他卡牌。

放置区已满时，不能继续盖伏防御牌，也不能发动需要进入放置区的永续卡。

防御牌规则：

- 防御牌必须从手牌盖伏到放置区。
- 防御牌只能在己方行动阶段从手牌盖伏。
- 盖伏不消耗单位行动额度。
- 盖伏不是发动，不结算卡牌效果。
- 当前不设每回合盖伏数量上限。
- 只要放置区有空位，且没有全局限制禁止盖伏，控制者可以继续盖伏防御牌。
- 防御牌盖伏当回合不能发动。
- 从其控制者本回合结束后开始，进入可触发状态。
- 防御牌能否发动，仍需满足发动区域、响应事件、触发条件、全局限制和目标合法性。

当前默认规则下，对方回合可发动的卡牌主要来自已盖伏并进入可触发状态的防御牌。

法术牌默认只能在己方行动阶段从手牌主动发动。若某张手牌卡允许在对方回合、墓地、除外区或响应链中发动，必须由卡牌文本明确声明发动区域、响应事件和触发条件。

一次性防御牌发动后离开放置区并进入结算；结算后的去向按卡牌去向规则处理。

永续卡可以同时包含发动时效果和留场持续效果：

- 发动时效果：在卡牌发动后进入响应链；若未被反制 / 无效，则按后发先至规则结算；结算完成后，其结果成立。
- 留场持续效果：永续卡成功结算后保留在放置区；只要留在放置区，其持续效果保持生效；离开放置区后，持续效果立即停止。
- 破坏已经成功结算并留场的永续卡，只停止其仍在维持的持续效果，不撤销其发动时已经结算完成的一次性结果。

装备 / 附着物默认不占用放置区，除非卡牌文本明确写明。

## 卡牌文本例外

默认规则处理大多数卡牌。卡牌文本可以覆盖默认规则，但只能覆盖其明确写到的部分。

卡牌文本可以覆盖：发动区域、发动事件、发动条件、目标模式、目标范围、结算效果、结算后去向、持续时间、是否留场、是否装备 / 附着、是否强制触发、是否可在响应链中发动、是否改变行动额度或区域规则。

卡牌文本不能绕过：统一卡牌使用流程、目标合法性校验、区域合法性校验、原拥有者 / 当前控制者规则、死亡检查规则、战斗事件规则。

## 卡牌发动合法性

所有卡牌发动前必须进行合法性校验。

校验顺序：

1. 区域合法性：卡牌是否位于允许发动的区域。
2. 类型合法性：当前事件或阶段是否允许该类型卡牌发动。
3. 全局限制：是否存在禁止发动、禁止类型、沉默、封印、规则改写等限制。
4. 卡牌自身条件：卡牌文本声明的发动条件是否满足。
5. 目标合法性：需要目标时，必须存在并选择合法目标。
6. 区域容量与必要条件：放置区、手牌、牌库、检索对象等是否满足必要条件。
7. 发动成功：全部通过后才视为发动成功。

当前没有战斗内费用系统。不检查法力、灵力、能量费用。构筑分只用于玩家卡组合法性。

没有合法目标，不能发动。取消目标选择，不算发动。卡不离开原区域。

一旦发动成功，卡牌离开原发动区域进入结算状态。后续即使目标消失、效果被反制或部分失败，默认也按发动成功处理去向，除非卡牌文本明确改变。

## 统一卡牌使用流程

所有出牌行为适用同一流程：

1. 卡牌使用 / 发动请求。
2. 判断是否需要目标。
3. 进入目标选择。
4. 校验目标是否合法。
5. 校验区域、事件 / 阶段、类型、全局限制和特殊条件。
6. 发动成功。
7. 卡牌离开原区域。
8. 进入响应时点或直接结算。
9. 按效果结算规则结算效果。
10. 按默认规则或卡牌文本移动到墓地、除外区、放置区、装备 / 附着物区、手牌或牌库。
11. 产生战斗事件。

## 卡牌去向

墓地是卡牌使用后的默认去向。

- 普通一次性卡发动并结算后，默认进入原拥有者墓地。
- 一次性放置区卡已发动后，即使效果失败，默认进入原拥有者墓地。
- 被反制 / 无效的卡牌仍视为已经发动，默认进入原拥有者墓地，除非文本明确改变去向。
- 被破坏的场上卡牌默认进入原拥有者墓地。

非墓地去向必须由卡牌文本明确写明，例如留在放置区、装备到单位、附着到单位、回到手牌、回到牌库、进入除外区、转移控制权。

## 破坏、反制和解除

当前底层区分破坏、反制 / 无效、解除 / 驱散三类处理。

破坏：处理已经在场上的对象，使其离场，默认进入原拥有者墓地。

可破坏对象包括：盖伏牌、永续卡、装备、附着物、其他明确可被破坏的场上对象。

破坏只作用于场上对象。手牌、牌库、墓地、除外区中的卡牌不使用破坏规则处理；若效果要处理这些区域中的卡牌，应使用丢弃、送入墓地、除外、返回牌库、加入手牌、移出当前卡组等明确区域移动文本。

破坏未发动的盖伏牌时，该牌不能再发动。

破坏已经进入响应链的来源时，默认不取消该链节。只有效果明确写明“反制”“无效”“取消该效果”时，才阻止该链节结算。

反制 / 无效：取消尚未结算的卡牌或效果链节。被反制 / 无效的链节不结算。该卡牌仍按发动成功后的默认去向处理。

反制 / 无效只能作用于已经发动但尚未结算的链节。响应窗口关闭且链节开始结算后，不能再对该链节反制 / 无效。已经结算完成的效果不能被反制 / 无效，只能被后续效果处理其结果。

解除 / 驱散：移除状态、装备、附着物、永续效果或持续效果。解除不等于破坏。解除后的去向由对象类型和卡牌文本决定。

卡牌文本若只写“破坏”，不得默认当作反制 / 无效。卡牌文本若要阻止已经发动的效果，必须明确写明反制、无效或取消效果。

## 原拥有者与当前控制者

卡牌原拥有者在对局中默认不改变。

抢夺、借用、控制、装备转移只改变当前控制者，不改变原拥有者。

卡牌离开当前控制区域并进入手牌、牌库、墓地、除外区等归属区域时，默认进入原拥有者的对应区域。只有卡牌文本明确写明改变拥有者时，才允许改变原拥有者。当前默认不做永久改变拥有者效果。

## 事件驱动时点、响应窗口和响应链

时点由战斗事件产生。

战斗事件包括但不限于：

- 回合开始抽卡完成。
- 行动阶段开始。
- 回合结束前。
- 卡牌效果即将结算。
- 单位攻击即将结算。
- 单位防御即将结算。
- 状态效果即将结算。
- 永续效果即将结算。
- 装备 / 附着物效果即将结算。
- 单位死亡确认。
- 单位离场。
- 抽牌、获得卡牌、移动卡牌。
- 其他由卡牌文本声明可响应的事件。

每当战斗事件进入待结算状态时，系统检查所有可响应来源。

可响应来源包括：

- 已盖伏并进入可触发状态的防御牌。
- 卡牌文本明确允许从手牌发动的响应牌。
- 卡牌文本明确允许从墓地、除外区或其他区域发动的效果。
- 场上永续卡、装备、附着物、状态或单位提供的可触发效果。
- 其他明确声明可在该事件响应的来源。

卡牌或效果不能无事件随意发动响应。必须存在一个战斗事件，并且该卡牌或效果声明可以响应该事件，才会进入响应候选。

若没有任何合法可响应来源，则不显示响应窗口，事件直接结算。

若存在合法可响应来源，则打开响应窗口，由对应控制者选择是否发动。

响应链规则：

1. 某个战斗事件进入待结算状态。
2. 系统检查强制触发、可选触发和合法响应。
3. 没有合法响应时，事件直接结算。
4. 强制触发先进入响应链；同一阵营多个强制触发按来源稳定顺序入链。
5. 双方强制触发同时满足时，非当前事件发起方优先；无法判断事件发起方时，非当前回合方优先。
6. 强制触发入链后，进入可选响应。
7. 同一待响应对象上，非当前事件发起方优先获得响应机会；其跳过后，当前事件发起方获得响应机会。
8. 控制者可以发动满足条件的卡牌或效果。每发动一个响应，形成一个新的链节。
9. 新链节形成后，该链节成为新的待响应对象，双方继续获得响应机会。
10. 控制者在一次响应机会中选择跳过，表示不对当前待响应对象追加链节；若之后对方追加新链节，且新链节满足己方响应条件，仍可再次获得响应机会。
11. 双方连续跳过后，响应链关闭。
12. 响应链关闭后，整条响应链锁定并开始结算。
13. 响应链从最后形成的链节开始，按后发先至顺序一次性逐个结算。
14. 响应链结算期间，链结算优先级最高，不再插入新的响应、反制或链节。
15. 链结算中产生的生命归零、离场、区域移动、状态变化等系统结果正常成立。
16. 链结算中产生的可触发效果，不插入当前链；当前链全部结算完成后，作为新的战斗事件处理。
17. 整条响应链结算完成后，回到原事件流程继续。

结算完成后的结果不能再被反制。若当前阶段仍允许行动，控制者可以继续发动新的卡牌、行动或效果；这属于新的战斗事件和新的响应链，不是对上一条响应链的干涉。

防御牌默认是可选触发。只有卡牌文本明确写明强制触发时，才自动发动。

## 效果结算

效果结算规则负责处理通用效果步骤：

- 造成伤害。
- 失去生命。
- 治疗。
- 加状态。
- 移除状态。
- 抽牌。
- 检索。
- 向指定区域加入指定卡牌。
- 添加装备 / 附着物。
- 破坏场上对象。
- 反制 / 无效响应链节。
- 解除 / 驱散状态、装备、附着物或持续效果。
- 改变攻击。
- 改变防御。
- 附加下一次攻击效果。
- 召唤单位。
- 改变行动额度。
- 触发事件。

具体卡牌效果由通用效果步骤组合表达。

“向牌库加入指定卡牌”不是特殊底层类型。加入的卡牌必须来自统一卡牌数据库，可以是无效果废卡，也可以是带负面效果的干扰牌。

攻击、防御、抽牌数、行动额度等数值修正使用统一修正规则。

## 伤害、生命和死亡

伤害和失去生命是不同底层效果。

造成伤害：

- 经过防御计算。
- 可受破甲、减伤、增伤、攻击修正影响。
- 可触发“受到伤害时”“造成伤害时”。

伤害公式：

`最终伤害 = max(0, 基础伤害 - 当前有效防御)`

当前有效防御允许为负。负防御会增加最终伤害。

失去生命：

- 不经过防御计算。
- 不被普通防御抵消。
- 默认不触发“受到伤害时”，除非文本明确写明。

治疗：恢复生命，不超过最大生命，除非文本明确突破上限。

死亡检查只看生命值结果，不看来源。只要单位生命值归零或低于 0，立即进入死亡结算。

死亡结算：

1. 单位生命归零，进入死亡结算。
2. 若没有防止死亡、替死、复活等明确效果，确认死亡成立。
3. 单位离场。
4. 普通状态移除。
5. 装备 / 附着物按规则离场。
6. 检查胜负。
7. 死亡时效果作为战斗事件处理。

若死亡发生在响应链结算过程中，死亡时效果不插入当前响应链；当前链全部结算完成后，作为新的战斗事件处理。

单位生命归零后即视为死亡。死亡时效果默认不能取消本次死亡。只有文本明确写明“防止死亡”“替死”“复活”时，才可改变死亡结果。当前未设计复活 / 替死效果时，玩家主单位生命归零即确认死亡成立。

玩家主单位死亡成立后，玩家战败优先于敌方全灭胜利判定。

已离场单位不能继续作为普通效果目标。多段效果中，若目标在前一段中死亡，后续仍以该目标为对象的效果不再施加，该卡仍视为已成功结算。

## 状态

状态是单位身上的效果实例，由数值变动、计数器、触发规则、持续规则和移除规则组成。

状态分为：

- 永续状态：无时间限制，除非被效果解除或宿主离场。
- 时效状态：带计数器，在指定事件触发并衰减，计数归零后移除。

所有时效状态必须声明触发事件、触发效果、衰减方式和移除条件。未声明触发事件的状态不得进入活跃内容。

状态以实例形式存在。

- 每个状态实例独立记录来源、名称、数值、持续计数、触发事件和移除条件。
- 同名状态默认允许多个实例并存。
- 多个同名状态不自动叠加、不自动刷新、不自动取最大。

状态可以带标签。状态标签只用于检索、清除、驱散和规则判断，不改变状态自身结算逻辑。

常用状态标签包括正面、负面、中性、中毒、破甲、虚弱、减伤、增攻、特殊。

未声明正面或负面的状态，默认视为中性。

清除负面状态、清除正面状态、清除全部状态等效果，按状态标签处理。

状态默认可以被对应驱散 / 清除效果处理。若某个状态不可驱散、不可清除或只能被指定效果处理，必须由状态数据或卡牌文本明确声明。

状态文本决定其效果属于造成伤害还是失去生命。

当前 active 状态的正式规则：

- `poison` / 中毒：每次施加 2 层时创建 1 个独立实例。该实例每次在持有者所属阵营正式回合开始抽卡完成后，使持有者失去 1 点生命，然后计数 -1，归零移除。开局抽牌、卡牌效果抽牌和其他非回合抽牌不触发中毒。中毒属于失去生命，不经过防御、下次减伤或伤害修正。
- `armor_break` / 破甲：每次施加创建 1 个独立实例，降低持有者防御 1 点。多个实例的数值合计生效，防御可以低于 0。持有者行动阶段结束时每个实例计数 -1，归零移除。
- `weak` / 虚弱：每次施加创建 1 个独立实例，降低持有者攻击 1 点。多个实例的数值合计生效，最终攻击最低为 0。持有者行动阶段结束时每个实例计数 -1，归零移除。
- `next_damage_reduce` / 下次减伤：每次施加创建 1 个独立实例，数值为 3。持有者受到正数伤害时，当前所有下次减伤实例按创建顺序一起触发并全部移除，抵扣值为实例数值总和，最终伤害最低为 0，过量抵扣不保留。失去生命不触发下次减伤。

按标签清除 1 个状态时，移除 1 个完整状态实例；存在多个匹配实例时，移除最早创建的实例。中文状态名只作为显示、日志和本地化文本；正式规则键使用英文 canonical ID。

## 装备和附着物

装备本质是带来源卡牌身份的持续附着物。

- 装备保留卡牌身份。
- 装备挂载在单位身上。
- 装备可提供攻击、防御或其他持续修正。
- 装备可被破坏、抢夺、解除、弹回、除外。
- 普通状态解除不默认解除装备。
- 装备吃专门的装备处理效果。

装备型卡牌必须选择合法装备目标。目标不合法时不能发动。目标在结算前死亡或离场时，装备失败；已发动卡牌按默认去向或文本指定去向处理。

单位死亡并离场时，其身上的装备 / 附着物默认离场。装备卡默认进入原拥有者墓地。若卡牌文本写明回手牌、回牌库、除外、转移或保留，则按卡牌文本处理。
