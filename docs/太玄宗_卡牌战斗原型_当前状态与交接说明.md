## 2026-07-05 补充：探险外壳 MVP

当前主流程已经从“启动后直接选职业并进入连续战斗”调整为：

1. 开始菜单。
2. 职业选择。
3. 探索地图。
4. 点击地图节点进入战斗。
5. 战斗胜利后选择 1 张奖励卡。
6. 奖励加入本轮卡组，然后返回探索地图。

当前新增文件：

- `scenes/MainMenuScene.tscn`
- `scripts/ui/MainMenuScene.gd`
- `scenes/MapScene.tscn`
- `scripts/ui/MapScene.gd`
- `scripts/run/RunState.gd`
- `scripts/run/MapGenerator.gd`
- `scripts/tests/RunFlowSmokeTest.gd`

当前实现边界：

- 地图是原型用固定 7 层路线，包含普通、精英、首领节点。
- 玩家只能从底层可用节点开始，完成节点后沿连接路线向上推进。
- 当前只有战斗节点，事件、商店、休息、宝箱等节点类型还没有实现。
- 战斗仍是单敌人模型；精英和首领暂时通过生命、攻击、防御数值修正区分。
- 多敌人阵容、持久生命、遗物、金币、地图奖励分层等系统暂未接入。
- `BattleManager.start_run()` 仍保留原连续战斗测试模式；探险模式使用 `start_run_with_deck()`，奖励选择后进入 `map_complete`，由 `Main.gd` 接回地图。

当前建议：

- 在 Demo 阶段继续优先补齐可玩闭环和关键手感，不急着做全量架构重构。
- 每次新增系统级交互后，同步写入本交接文档和修改记录，后续重构时就能从文档和代码共同整理出明确需求。
- 多敌人战斗会影响目标选择、敌方意图、伤害结算、UI 布局和卡牌描述，建议单独作为一轮较大的战斗系统扩展处理。

## 2. 当前项目阶段

当前版本是可运行卡牌战斗 Demo，不是最终工程形态。

当前目标是验证：

- 基础卡牌战斗规则是否可玩。
- 职业差异是否成立。
- 卡组、手牌、墓地、除外区流转是否稳定。
- 法防区、装备区、时点、连锁的基础框架是否可扩展。
- 战斗界面能否从文字面板逐步过渡为卡牌战斗场景。

未来当职业、卡牌、敌人、奖励、地图、视觉反馈都进一步确定后，需要重新评估场景划分、脚本职责、数据结构和表现层事件系统。

## 3. 当前已确定的基础规则

保留的规则：

- 启动后选择职业：剑修、符修。
- 选择职业后进入战斗。
- 战斗开始抽 5 张牌。
- 玩家回合开始抽 1 张牌。
- 当前暂不设置手牌数量上限。
- 玩家每回合可以普通攻击 1 次。
- 普通攻击伤害为 `攻击力 - 防御力`。
- 伤害小于等于 0 时不造成伤害。
- 有卡组、手牌、墓地、除外区。
- 卡组抽空时，墓地洗回卡组。
- 除外区不参与洗牌循环。
- 有法防区，容量 5 格。
- 有装备区，默认容量 2。
- 防御牌和永续法术牌共用法防区。
- 装备牌进入装备区，不占法防区。
- 战斗胜利后进入奖励界面，然后可进入下一场。
- 连续 5 场后循环回第 1 场。

## 4. 职业状态

当前已有职业：

- 剑修
- 符修

剑修：

- 拥有剑势。
- 普通攻击命中后获得 1 点剑势。
- 可以消耗剑势使用剑修终端牌，例如小无相剑、一剑开天。

符修：

- 没有专属资源。
- 依赖符牌、回收符牌、复制符牌等机制。

当前不要新增职业，除非用户明确提出。

## 5. 卡牌区域与装备替换

装备区当前默认容量为 2，但已经改为从 `PlayerState.equipment_limit` 读取，方便未来职业或效果突破上限。

装备满时：

1. 玩家点击新的装备牌。
2. 不再只写日志失败。
3. 进入装备替换模式。
4. 当前装备卡发光，提示玩家选择要卸下的装备。
5. 点击一个已装备卡后出现确认面板。
6. 确认后，旧装备进入墓地，新装备进入装备区。
7. 被替换下来的装备会移除自身提供的攻击/防御加成。

默认规则：

- 装备被替换、破坏或移除时进入墓地，除非卡牌效果另有说明。

## 6. 防御牌与时点规则

当前已修正的防御牌就绪规则：

- 防御牌盖伏的当前玩家回合不能发动。
- 玩家点击结束回合后，本回合盖伏的防御牌即进入 ready 状态。
- 敌人回合中，刚刚在玩家回合盖伏的防御牌可以响应敌人行动。
- 不需要等到玩家自己的下一个回合。

注意：如果旧执行文档中仍有“下一回合或更晚”之类表述，以本交接说明为当前实现准则。

## 7. 连锁交互当前约定

当前不再使用旧的大响应弹窗。

进入响应时点时：

1. 画面中间显示大字“连锁”。
2. 中央下方显示当前时点和当前连锁状态。
3. 可响应的场上盖伏卡在原位置发光。
4. 玩家鼠标悬停可查看盖伏卡真实信息。
5. 点击可响应盖伏卡后，该卡被选中并出现确认面板。
6. 点击“发动”后加入连锁。
7. 点击“取消”只取消当前选中。
8. 点击“结束连锁”相当于跳过响应。

未来如果支持手牌响应，也应复用同一套“可响应对象发光 + 点击确认”的交互，但当前版本先只处理场上盖伏卡。

## 8. 战斗 UI 当前约定

整体方向：

- 不再做大资料面板拼接。
- 战斗界面应像“完整战斗场景上浮着卡牌 UI”。
- 玩家和敌人是固定战斗单位占位，不随文字和日志变化拉伸。
- 日志是覆盖式浮层，不挤压主战斗区。

玩家与敌人：

- 玩家位于左侧偏中。
- 敌人位于右侧偏中。
- 双方显示占位框、血条、血量、攻击/防御。
- 剑修额外显示剑势。
- 敌人显示当前意图。

法防区：

- 位于玩家右侧附近。
- 固定 5 个槽位。
- 空槽是半透明虚框。
- 盖伏防御牌显示卡背。
- 永续法术牌正面显示。
- 可响应时显示呼吸光提示。

装备区：

- 位于玩家左侧附近。
- 不是横向排列，而是纵向小卡堆叠。
- 当前最多 2 张，但 UI 已按未来更多装备数量做堆叠适配。
- 场上装备卡使用绿色风格，与手牌装备卡一致。

手牌区：

- 位于屏幕底部中央。
- 每张手牌是竖向卡牌。
- 卡名、类型/标签、效果描述分层显示。
- 手牌没有数量上限。
- 展示区域有最大宽度。
- 手牌过多时自动水平叠放，右侧牌层级更高。
- 鼠标悬停时，卡牌上浮、略放大、提升到最上层。
- 目前只有手牌区保留上浮 / 放大的 hover 表现。

完整大卡：

- 手牌、选择面板、奖励面板、牌堆查看窗口中的卡牌都使用完整大卡模板。
- 选择面板、奖励面板、牌堆查看窗口中的完整大卡悬停时只保留高亮，不上浮、不放大。
- 完整大卡内容已经清晰显示，不再额外弹出悬浮说明框。
- 悬浮说明框只用于法防区、装备区等缩略卡。

卡组、墓地、除外区：

- 以小型牌堆按钮显示数量。
- 点击后打开覆盖式查看浮窗。
- 查看窗口不挤压主战斗界面。
- 查看窗口是模态交互，打开时背景有半透明黑色遮罩，外部战斗 UI 不可操作。
- 点击右上角“关闭”或点击查看窗口外任意位置都会关闭窗口。
- 查看窗口内的卡牌悬停时只保留高亮，不做手牌区的上浮 / 放大位移。

## 9. 当前视觉反馈状态

已经有的基础反馈：

- 普通攻击前冲。
- 受击抖动 / 闪红。
- 伤害跳字。
- 回复跳字。
- 剑势变化跳字。
- 减伤、打断等提示。
- 可响应盖伏卡呼吸发光。
- 防御牌发动后高亮 / 结算反馈。
- 装备替换时可替换装备发光。
- 使用手牌、盖伏防御牌、确认装备替换时有轻量上浮 / 淡出 / 线框残影动画。
- 盖伏落位、永续法术进入法防区、防御牌发动、连锁结算时，目标法防区槽位有一次性光晕脉冲。
- 装备牌进入装备区时，目标装备槽位有一次性光晕脉冲。
- 手牌释放残影节奏偏快，只用于提示“这张牌已被使用”，避免长时间遮挡视线。

当前音效状态：

- 当前使用程序生成的占位短音效，不依赖外部音频素材。
- 已接入手牌悬停翻卡声、出牌声、盖伏声、永续放置声、装备声、攻击声、受击声、回复声、防御牌发动声、连锁声、胜利声、卡牌破坏声和基础 UI 点击声。
- 手牌悬停音效只在手牌卡牌实际上浮时触发，选择面板、奖励面板、牌堆查看窗口不会触发翻卡移动音效。
- 敌人破坏法防区卡牌时会触发卡牌破坏音效。
- 这些音效只用于验证反馈节奏和操作手感，后续正式素材可以通过 `AudioManager.register_stream()` 替换。

本轮已完成的视觉反馈优化：

1. `ZoneSlot` 已拆成底层光晕层和上层卡牌面板。
2. 呼吸光不再调亮卡牌本体，而是在卡牌下方独立播放。
3. 光晕范围比卡牌略大，表现为卡牌外圈发光。
4. 呼吸动画以光圈范围扩张 / 收缩为主。
5. 盖伏落位时只做一次光晕脉冲。
6. 装备替换可选装备也复用同一光晕接口。
7. 装备牌进场、永续法术进法防区也复用同一光晕接口。

## 10. 已完成任务：视觉反馈优化

本轮已完成原第 10 节建议任务。

### 10.1 独立底层光晕

`ZoneSlot` 的发光表现已经重做：

- 卡牌本体保持原色。
- 发光层放在卡牌下方。
- 光晕尺寸比卡牌略大。
- 光晕随时间缓慢扩张、收缩。
- 可响应状态持续呼吸。
- 盖伏落位时只做一次脉冲。
- 装备替换可选装备也复用同一光晕接口。

### 10.2 手牌发动特效

点击使用手牌后，已有轻量卡牌发动动画：

- 卡牌从手牌位置向上快速浮起一小段。
- 同时透明度下降。
- 实体逐渐虚化。
- 边框可以稍微保留，形成“线框残影”。
- 最后消失。
- 动画不要太夸张，不影响操作节奏。
- 残影层级高于手牌悬停层，避免被鼠标下方的新手牌遮住。

实现建议：

- 规则仍由 `BattleManager` / `CardResolver` 结算。
- UI 复制视觉残影播放动画。
- 动画逻辑没有写进具体卡牌效果。

### 10.3 盖伏反馈

防御牌从手牌盖伏到法防区时：

- 使用手牌发动类似的轻量上升/消失反馈。
- 目标法防区槽位做一次光晕脉冲。
- 然后显示卡背。

## 11. 当前临时实现与风险
