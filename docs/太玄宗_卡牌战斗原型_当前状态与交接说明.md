# 太玄宗卡牌战斗原型：当前状态与交接说明

## 当前定位

项目仍是 Godot 4 Demo / 原型验证期。当前目标是继续扩展可玩内容和战斗手感，不做一次性大重构。

更合适的节奏是：

1. 先设计和实现一批真实卡牌、敌人、精英和敌方卡组。
2. 新效果优先复用现有战斗单位、阵营侧和效果步骤。
3. 只有当多张卡或多个敌人反复需要同类能力时，才抽成新的通用模块。
4. 每次实际改动后同步文档，并跑无头检查。

## 当前主流程

1. 开始菜单。
2. 选择角色：剑修或符修。
3. 进入角色准备界面，可查看角色成长、卡包解锁和开局构筑。
4. 点击开始挑战后进入三层主线探索。
5. 选择战斗、事件、宝箱、坊市或休息节点。
6. 战斗胜利后选择 1 张奖励卡并获得灵石。
7. 奖励优先进入当前卡组；如果张数或分数不允许，则进入备牌区。
8. 在地图中可随时调整当前卡组和备牌区。
9. 击败第一、二层首领后进入下一层地图。
10. 击败第三层首领或中途战败后进入探索结算页，将已完成节点收益写入当前角色 / 职业的局外成长。

## 当前战斗规则

- 战斗只有我方阵营和敌方阵营两个“牌手”，按阵营回合推进；不要把场上单位理解为各自拥有独立回合、独立牌手或独立卡组。
- 每边当前最多 3 个单位：主单位居中，额外单位在前上 / 前下。单位类似场上的怪物 / 角色承载体，只承载生命、攻击、防御、装备、状态、资源和可被卡牌影响的字段。
- 当前我方阵营回合内，每个存活我方单位可获得一次基础行动额度。这个额度只代表该单位可以攻击或防御一次，不代表该单位拥有自己的回合。
- 基础行动按钮直接显示在我方单位卡下方：`攻击 / 防御`。
- 防御当前为本单位防御力翻倍，持续到下一个玩家回合开始。
- 如果单位当前防御力为 0，执行防御时临时获得 1 点防御，持续到下一个玩家回合开始。
- 默认伤害都会被目标防御力减免；只有明确写“无视防御”的效果才绕过防御。
- 当前已接入第一批通用状态：破甲降低防御，虚弱降低攻击，灼伤在回合结束造成伤害并衰减，迟滞降低下一次行动威力。
- 当前已接入“下次减伤”状态，用于表达一次性减伤类低分卡。
- 敌方回合内，敌方阵营按队列驱动场上存活单位进行基础行动；这仍然是敌方阵营回合，不是单位各自开回合。
- 敌方阵营牌手已经统一抽牌和出牌：非终极首领敌方起始手牌为 0；普通遭遇每敌方回合抽 1，精英抽 2，首领抽 3。
- 敌方阵营会在单位基础行动队列前统一尝试出牌；普通 / 精英 / 首领的差异主要来自阵营抽牌数、卡组模板、牌组大小和卡牌延迟，而不是给每个单位写独立出牌逻辑。
- 普通攻击伤害为攻击力减防御力；小于等于 0 时不造成伤害。
- 我方失败条件是我方主单位死亡；非主单位血量归零会退场并释放阵位。
- 敌方失败条件是敌方场上单位全部死亡。敌方普通 / 精英 / Boss 都是敌方阵营控制的场上单位；终极 Boss 后续可以作为例外，接近玩家规则拥有完整对局感。
- 同一结算中如果我方主单位和敌方单位同时归零，我方主单位死亡优先，判定为战败。
- 我方战斗开局抽 5 张；第一个我方回合不额外补抽；后续我方回合抽 1 张。
- 抽卡动画期间锁定操作，卡牌从右下卡组飞入手牌后再揭示。

## 区域与卡牌

- 我方和敌方都有阵营侧区域：单位、牌库、手牌、墓地、除外区、放置区。
- 敌方手牌、牌库、墓地和除外区当前在后台运行，UI 不显示。
- 双方放置区各 5 格，位于主单位下方横排。
- 防御牌需要先盖伏，满足时点后才能发动。
- 明牌放置牌可进入放置区，占用 1 格，并支持倒计时、触发次数、压牌和自动结算。
- 放置区槽位会显示倒计时、剩余触发次数和被压牌数量。
- 盖伏响应 UI 使用“发动盖伏卡 / 发动 / 结束发动”文案。
- 盖伏响应和普通攻击目标选择共用中上方 `ResultPreviewLabel` 结果预览区。
- 装备牌仍通过 `after_use = "equipment"` 进入装备流程。
- 装备已支持复合效果和濒死保护类通用效果。
- 所有单位都有装备槽：普通 1、精英 2、首领 3、我方主单位 2。
- 我方手牌中的装备牌可拖到我方任意存活单位，替换和攻防加成都按目标单位处理。
- 卡牌效果文本和数据后续应尽量使用阵营相对概念，例如“我方主单位”“敌方主单位”“选定我方单位”“选定敌方单位”，避免把通用效果写死为“玩家”。

## 探索与卡组

- 当前不再走局内 Boss 后突破流程；第一、二层 Boss 胜利只推进到下一层地图，第三层 Boss 胜利才进入本轮探索结算页。
- 练气、筑基、金丹、元婴、化神、渡劫暂时作为局外称号阈值展示，不直接驱动局内升级池。
- 标准主线为三层爬塔；每层是一张地图。层间刷新地图并回复生命，但不提供局内境界属性成长。
- 隐藏 Boss、完整牌手对手、Boss 连战和劫数属于通关后系统，不进入普通三层主线。
- 玩家生命跨战斗继承；局外成长提供的最大生命、攻击、防御、基础抽牌和卡组总分上限在开局时生效。
- 当前卡组保存时必须在 10 到 20 张之间。
- 每张卡有 `build_cost`，界面显示为“分数”。
- 地图和卡组界面显示“卡组总分”，不能超过当前职业局外成长后的分数上限。
- 备牌区不参与战斗，不计入卡组张数和卡组总分。
- 本轮每完成节点获得基础修为点：普通 3，事件 / 坊市 / 休息 2，宝箱 4，精英 5，首领 10；第三层 Boss 或中途战败结算时按最终到达层倍率写入当前职业。战败时只统计已经完成的节点。
- 职业成长点当前名为“修为点”，按职业分别保存到 `user://progression.json`。
- 当前职业成长池包含最大生命、攻击、防御、卡组总分上限、基础抽牌、编号卡包开放批次和剑修开局剑势；当前价格已按三层制收益重标定，基础生命从 12 点起，基础抽牌属于 160 点的后期强成长。
- 角色成长页现在按基础属性、卡组与卡包、角色特性和强力规则等分类展示；分类字段只服务 UI，不改变现有存档结构。
- 奖励、事件、宝箱和坊市会按当前职业已开放的编号卡包过滤；旧 `card_unlock_tier` 仍作为兼容字段，0 对应 `common_1 + 职业_1`，1 额外开放第二批，2 额外开放第三批。起始牌组不受该过滤影响。卡牌定义已由 `CardDefinitionDatabase.gd` 统一提供；旧 `CardDatabase.gd` 保留兼容入口、卡牌实例 uid 和解锁元数据补齐；编号卡包、通用 / 职业卡池、奖励池过滤和坊市库存来源已由 `CardPoolDatabase.gd` 统一提供；战斗奖励、宝箱 / 事件卡牌来源和奖励数值已由 `RewardService.gd` 统一提供；奖励、商店、事件和战斗奖励的入卡去向已由 `CardAcquisitionRules.gd` 统一提供；坊市刷新、购买和出售已由 `ShopService.gd` 统一提供；事件种类、事件选项和普通 / 奇遇 / 交易事件结果已由 `EventService.gd` 统一提供；节点修为、休息恢复和探索结算数值已由 `ExplorationRules.gd` 统一提供；战斗启动 payload、战斗回流、首领层间推进和放弃探索已由 `RunState.gd` 统一提交。
- 角色准备页的卡包解锁会列出通用 1-5 和当前职业 1-5 的槽位、开放状态和当前已有卡数，同时显示当前识藏等级、下一批卡包和开放成本；修为点足够时可直接在该页提升识藏。
- 角色准备页的开局构筑会列出当前卡组和备选池；备选池当前由职业默认开局牌和已开放编号卡包组成，开始挑战时只把当前卡组传入本轮 `RunState`。
- 准备页备选池不会作为探索备牌带入本轮，避免未选卡开局即可在坊市出售；探索备牌仍来自本轮奖励、购买或地图中移出的卡。
- 开局构筑仍只检查 10-20 张和卡组总分上限，不引入同名卡限制，也不代表已经完成永久收藏 / 卡牌库存系统；该合法性现在由 `DeckBuildRules.gd` 统一提供，准备页、地图页和奖励入卡入口共用。
- 如果某类遭遇按分数段过滤后候选少于 3 张，会在同一已解锁卡包范围内放宽分数下限，避免低卡包阶段 Boss 奖励只有 1 张可选。
- 当前不做同名卡数量限制，不做稀有度式限制，也不做强制删牌式肉鸽逻辑。
- 当前不做五行或属性克制规则；属性感词汇只作为卡名和风味，不参与额外结算。
- 当前剑修和符修初始防御力均为 0；低层普通敌人也以 0 防御为主，防御属性后续再逐步变稀有、变重要。
- 探索状态生命为 0 时不再提供可选节点，也不能进入战斗；避免 0 血在地图上继续靠事件或休息恢复。

## 本次清理后的约定

- 旧 `ResponsePanel` 响应弹窗已删除；当前只使用 `BattleScene` 内的 `ChainOverlay` 和场上发光槽位。
- 旧单体 `UnitActionPanel` 已删除；当前只保留单位卡下方内联按钮。
- 卡牌库不保留同名上限死代码；当前卡组约束只看张数和卡组总分。
- 剑修当前重做方向是我方主单位普通攻击：剑修牌优先提供剑势、攻击成长、额外攻击、群攻、多段和下一次攻击倍率。
- 首领胜利后不再触发局内突破升级；第三层首领胜利或中途战败会先显示探索结算页，局外成长在角色准备页购买。
- 标准探索已改为三层主线：第一、二层首领后刷新下一层地图，第三层首领后才结算局外修为点。
- 中途战败会保存已完成节点的修为点并进入探索结算页，避免失败局没有局外成长收益。
- 编号卡包兼容层已接入：当前已实现卡牌使用显式包表配置包归属；奖励、事件、宝箱和坊市统一按 `common_1 / sword_1` 等包名过滤。卡牌定义已迁入 `CardDefinitionDatabase.gd`；活跃卡池 / 卡包查询已迁入 `CardPoolDatabase.gd`；`CardDatabase.gd` 仍保留旧入口兼容、实例创建和解锁元数据补齐。
- 敌方底层已按文件拆为角色池、敌方卡组模板、难度曲线和遭遇组装工厂：角色池描述通用战斗单位；主线层数 + 节点位置 + 战斗类型 + 世界难度先选择敌方卡组模板，卡组模板再引用可出场角色、站位、阵营卡组、抽牌数和主题标签；难度曲线按层数、节点位置、遭遇类型和 `world_difficulty` 追加生命 / 攻击 / 防御；`BattleEncounterRuntime.gd` 负责把遭遇数据适配为战斗运行期需要的主敌人、敌方牌组 profile、抽牌数和出牌额度；`EnemyDatabase.gd` 暂时保留旧接口兼容。
- 当前每层普通 / 精英 / 首领都已经走敌方卡组模板池；第一层普通和精英世界难度 0 仍多为空牌包，第一层首领有 3 套 5 张轻牌包；第二层精英有 3 套 3-4 张模板，第二层首领有 3 套 6 张牌包；第三层普通有 3 套 3 张模板，第三层精英有 3 套 4 张模板，第三层首领有 3 套 7 张牌包。
