# 音频与反馈规范

## 当前状态

当前音效全部由程序生成，只用于验证操作节奏和反馈密度，不代表最终品质。

背景音乐当前只有事件占位和播放管理，没有正式音乐素材；没有素材时播放请求会安静失败，不影响主流程。

## 已接入音效

- 手牌悬停翻卡声。
- 出牌声。
- 盖伏声。
- 永续法术放置声。
- 装备声。
- 攻击声。
- 受击声。
- 回复声。
- 防御卡发动声。
- 盖伏响应开始与结算声。
- 胜利声。
- 卡牌破坏声。
- 基础 UI 点击与确认声。

## 当前原则

- 高频音效要短。
- 悬停音效必须有冷却。
- 出牌、放置、装备、受击要能听出区别。
- 胜利、破坏和盖伏发动可以更突出。
- 音频事件、类别、音量、冷却和未来素材路径由 `AudioEventDatabase.gd` 维护。
- 战斗事件到音效事件名的映射由 `BattleAudioRouter.gd` 维护。
- 具体音频流、程序占位音效、音效音量和播放节点由 `AudioManager.gd` 维护。
- 背景音乐播放、当前曲目、循环和音乐音量由 `MusicManager.gd` 维护；音乐事件仍登记在 `AudioEventDatabase.gd`。
- 主音量、音乐音量和音效音量属于 `GameSettings.gd` / `SettingsStore.gd` 的设置数据，音频播放节点只消费设置结果。
- 新增战斗音效时优先添加事件映射或音频事件，不要在战斗结算或 UI 事件分支里直接写一次性播放特例。
- 新增背景音乐时先登记 `music.*` 事件和素材路径，再由应用流程在场景切换时调用 `MusicManager`，不要让单个 UI 按钮直接加载音乐文件。

## 后续替换

正式音频素材先放入 `assets/audio/` 对应分区，再登记到 `AudioEventDatabase.gd` 和 `AssetAttributionDatabase.gd`；需要运行期替换一次性音效时可以通过 `AudioManager.register_stream()` 替换，背景音乐由 `MusicManager` 读取音乐事件路径，不需要重写战斗规则。

未来可拆分：

- 卡牌操作音效。
- 战斗打击音效。
- 法术音效。
- 装备音效。
- 地图环境声。
- 主菜单、地图和战斗背景音乐。
- 首领或章节提示音。
